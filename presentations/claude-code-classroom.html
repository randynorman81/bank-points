What Is Claude Code?

Claude Code is an AI assistant from Anthropic that works inside a folder on your computer. Instead of just chatting, it can read your files, write and edit them, run commands, preview web pages, and publish your changes — and it asks your permission along the way.

A regular AI chatbotClaude Code
Where it worksA chat windowYour actual project files
Writes code?Gives you code to copy and pasteCreates and edits the files itself
Tests its work?NoYes — runs it, previews it, clicks the buttons
Remembers your project?Only what you paste inReads the whole folder, plus notes about your preferences
Publishes?NoCan save versions and push them to your live site
Think of it as a very fast teaching assistant who happens to know how to build websites. You're still the teacher: you decide what gets built, you check it, and you decide what students see.
Keep this short. The key idea: it does the work in your files instead of handing you code to paste. Mention it runs in a desktop app, a terminal, VS Code, or the browser — you'll show the desktop app at the end.

How a Request Actually Works

Every job follows the same loop. You describe the result; Claude Code does the steps in between and checks in with you.

Here's what that looks like in the app (shortened):

my-class-site
> Change the schedule so we cover 2.7, 2.8, 2.9, and 2.10 this week, and shift the rest of the unit. Reading ist/pacing-guide.html, ist/unit-2/calendar.html… This week currently has 2.7–2.9. Adding 2.10 frees one slot, so the rest of Unit 2 moves up a week. The "Next Two Weeks" page reads from the pacing guide, so it will update automatically. Editing ist/pacing-guide.html (weeks 9–16)… Editing ist/unit-2/calendar.html… ✓ Checked: no other pages list these dates. ✓ Saved and published. The week of Nov 30 had 3 items, so the shift ends there — December is unchanged.
Notice what it did on its own: it found every place the schedule appears, explained its reasoning, checked for dates I didn't mention, and told me where the change stops. My whole job was one sentence and a quick look.
If you're showing it live, do a tiny request here instead (e.g., "change the footer text"). Point out the permission prompts: it asks before running commands or publishing, depending on your settings.

Five Real Requests, Start to Finish

These are real prompts I typed, lightly shortened. None of them is written in "computer" language.

REQUEST 1 · A STUDY GUIDE
create a complete study guide for APCSP unit 3 … make the questions the same as asked on the APCSP test, but focus on variables, string methods, user input, basic math, graphics, and mouse events
What Claude Code did
  • Read my existing notes pages so the guide matched what I teach
  • Wrote the review sections with diagrams and a small calculator for // and %
  • Built a 66-question, self-grading, AP-style practice test that explains every answer
  • Tested it on a phone-sized screen, then published it
My part
  • One paragraph describing what I wanted
  • Clicked through the practice test before sharing it with students
REQUEST 2 · GRADING A FOLDER OF ASSIGNMENTS
grade these out of 100 [link to a Google Drive folder of lab write-ups]
What Claude Code did
  • Found the assignment directions and built a rubric from them
  • Read every document, including the screenshots
  • Returned a score table with a reason for every deduction
  • Flagged a misconception several students shared, as something to reteach
My part
  • Corrected it: "they were able to work in partners" — it withdrew its similarity flags
  • Reviewed the scores before entering anything
💡 It drafts; I grade. It's fast at the first pass, and I'm still the teacher of record.
REQUEST 3 · REBUILDING THE YEAR
after this unit: november HTML, december CSS, january bootstrap, february website project and computer basics, march OS, april networking, may review
What Claude Code did
  • Counted the lessons against the school calendar and breaks
  • Warned me that November and December were overloaded, before changing anything
  • Suggested fixes, then rebuilt the pacing guide once I approved
My part
  • Said "don't rebuild yet — give me your thoughts" and got advice first
  • Said "make your suggested changes" when I was ready
REQUEST 4 · WHEN IT SAID NO
give me student email addresses for copying for 1A and 2B
What Claude Code did
  • Explained it won't sign in to my live admin page with my PIN on my behalf
  • Offered to build a Copy Emails button into my dashboard instead
  • Built it, tested it with made-up students, and published it
My part
  • Said "yes"
  • Now copying a class's emails takes one click
💡 It has guardrails around passwords and private data — and it usually offers a better way.
REQUEST 5 · THIS PRESENTATION
create a complete presentation… make it a website I can give everyone… put it on my website under a new tab "presentations"
What Claude Code did
  • Added a Presentations tab to every page of the site
  • Built the presentation with a slideshow mode, a timer, and speaker notes
  • Built the demo dashboard with made-up students so no real data is shown
My part
  • Told it the audience and the time limit
  • Reviewed it and practiced
Pick two to talk through in detail — Request 2 (grading, with the correction) and Request 4 (the guardrail) spark the best conversation. Mention the small daily asks too: "put them in last-name order," "grade it out of 150."

Protecting Student Data

AI tools are only as safe as the data you give them. These are the practices I recommend for anyone building classroom tools.

Do

  • Use student codes (like S-1A-014) instead of names wherever you can, and keep the code-to-name key in your gradebook
  • Check your district's AI and data-privacy policy (FERPA) before an AI tool touches student work
  • Use made-up data for demos, screenshots, and testing — like the demo dashboard
  • Keep teacher pages behind a PIN or school sign-in
  • Review everything AI grades or writes before students see it

Don't

  • Paste in grades, IEP/504 details, discipline, or health information
  • Give an AI tool your passwords (Claude Code won't sign in to live sites with them anyway)
  • Project a dashboard with real names on it
  • Publish anything you haven't opened and clicked through yourself
Keep this tight but serious. The codes-only toggle in the demo is a good example of privacy by design: ask for it when you build your own tools.

How to Start Using It This Week

You don't need to know how to code. You need a clear idea of what you want and ten minutes to try it.

  1. Get access. Claude Code is included with Claude's paid plans (Pro and above). Check claude.com/pricing and ask whether your district has a plan.
  2. Install the Claude desktop app and open the Code tab. (Comfortable with a terminal? You can also install Claude Code there or in VS Code.)
  3. Make an empty folder on your computer, such as my-class-site, and open it in Claude Code.
  4. Paste a starter prompt from below. Watch what it does and approve the steps it asks about.
  5. Open what it made and ask for one change at a time: "make the heading bigger," "add a dark mode," "make it work on phones."
  6. Put it online when you're happy: "help me publish this with GitHub Pages" — it walks you through it.
  7. Teach it your rules once. "Remember that I always want made-up names in examples." It keeps notes on your preferences for next time.

Starter prompts to copy

Tips for good results

Say who it's for

"For 9th graders who've never coded" gets a very different page than "for AP students."

Describe "done"

What should it look like, and what should happen when a student clicks?

Ask it to check

"Preview it on a phone-sized screen and test the buttons."

One change at a time

Small requests are easier to review and easier to undo.

Ask for advice first

"Don't change anything yet — what do you think?" gets you a plan to approve.

It can be wrong

Check facts, grades, and dates. Correct it in plain English and it fixes them.

If there's time, do step 4 live with the first starter prompt — a class page appears in about a minute. Point out the Copy buttons so nobody has to type.

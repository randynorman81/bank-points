Why Collaborate?

Collaboration means working with other people toward a shared goal. Most real software is built by teams, and even a single student's project improves when others test it and give feedback.

1

Different viewpoints

People with different backgrounds notice different problems and think of different solutions.

2

Fewer blind spots

A team that represents many kinds of users is less likely to build something that works for only one kind.

3

Better quality

Someone else reading your code catches mistakes you can no longer see.

4

Shared workload

Big projects can be split into parts that people build at the same time.

This connects to bias: a diverse team is more likely to notice when a program fails for a group of users.

02

Purpose and Function

Every program has a purpose and a function. They sound alike, but the exam treats them as different ideas.

PurposeFunction
It answersWhy does this program exist?What does this program do?
It describesthe problem it solves or the interest it serveshow the program behaves: the input it takes and the output it gives
Examplehelp students prepare for a testshows a question, checks the answer, and reports a score

Try it: write the spec for a program

Pick a program idea. See its purpose, what goes in, what comes out, and what makes it run.

A program can have many inputs and outputs. Input can be text, a click, a key press, a sound, a sensor reading, or a file. Output can be text, a picture, a sound, or a movement.

03

Events

Some programs run in a fixed order from start to finish. Many apps are event-driven: parts of the program run when something happens, like a tap, a key press, or a message arriving.

Sequential programEvent-driven program
What runs next?the next line, in orderwhichever code handles the event that just happened
Examplea program that asks three questions and prints a resulta phone game that reacts to every tap
Order of eventsdecided by the programdecided by the user (or the world)

The Karel and key-event lessons earlier in the course were event-driven: code ran when a key was pressed.

04

Documenting Your Program

Documentation is writing down what a program is for and how it works. In code it is mostly comments.

  • Purpose: a comment at the top saying why the program exists.
  • Procedures: what each one takes in (parameters) and gives back (return).
  • Tricky parts: why you wrote a line a certain way.
  • Credits: say where borrowed code came from.

Good comments help other people and future you understand the program, and they make collaboration possible.

AP

On the AP Exam

These are the ideas the exam asks about. Be ready to explain each one in your own words.

  • Collaboration brings diverse perspectives and finds mistakes, producing better programs. Know pair programming (driver and navigator).
  • Purpose is the problem a program solves. Function is what it does with input to make output.
  • Programs can have many inputs and outputs, and many are event-driven.
  • Documentation (comments) explains purpose and function so others can use and improve the code.

Know why you are building it, and build it with others.

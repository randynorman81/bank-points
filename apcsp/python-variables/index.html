Variables

Everything you need to know to start storing and using data in Python.

What is a variable?

A variable is a named box that holds a piece of data in your program's memory while it runs. Instead of typing the number 15 over and over, you can store it once under a name — like age — and use that name anywhere in your code. When the value changes, you only have to change it in one place.

age = 15 print(age)

Here, age is the variable. It now holds the value 15, and it will keep holding it until you tell Python to store something else there.

Naming a variable — what you can and can't do

Python has strict rules about what a variable name is allowed to look like, and separate, looser conventions about what a good variable name looks like.

Allowed

Letters, numbers, and underscores (_). Must start with a letter or an underscore — never a number.

Not Allowed

Spaces, punctuation (- @ ! # etc.), and starting a name with a digit.

Case-Sensitive

age, Age, and AGE are three completely different variables to Python.

Reserved Words

You can't name a variable after a word Python already uses for something else, like if, for, while, True, False, or class.

The equals sign: =

This is the single most important thing to unlearn from math class. In math, = is a statement that two things are equal — it works both directions. In Python, = is the assignment operator: it means "take whatever is on the right, and store it in the variable on the left." It only works one direction.

1

In math

x = 5 means x and 5 are the same value, always. You could just as easily write 5 = x — it means the same thing.

2

In Python

x = 5 means "store 5 in x." Writing 5 = x is a syntax error — you can't assign a value into the number 5.

Because it only flows one direction, a line like this makes perfect sense in Python even though it would be impossible in math:

x = 5 x = x + 1 print(x) # prints 6

Read x = x + 1 from the right side first: Python looks up the current value of x (5), adds 1 to get 6, and then stores that new value back into x. No equation is being "solved" — it's a two-step instruction: compute the right side, then save it to the left side. This exact pattern (take a variable, change it, save it back to itself) shows up constantly in AP CSP — counters, running totals, and loops all depend on it.

Variables can change

A variable isn't locked to one value, or even one type, forever. Assigning a new value with = always overwrites whatever used to be there — that's true even if the new value is a completely different type than the old one.

data = "hello" # data is currently a string print(data) # hello data = 42 # now data is an integer instead print(data) # 42

This is called dynamic typing — Python figures out a variable's type from whatever value is currently stored in it, and that can change every time you reassign it with =. Nothing about the name data changed; only what's stored inside it did.

This is also why the naming rules matter so much: Python doesn't care what type of data a name is "supposed" to hold, so a clear, descriptive name is the only clue a reader gets about what a variable is for.

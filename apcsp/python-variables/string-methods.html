String Methods

Every string already comes with a built-in toolbox attached to it — functions you call with a dot, like my_string.upper(), that check, clean up, or search text without you writing that logic yourself.

00

Definition

A string method is a function that belongs to a string, called with dot notation: variable.method_name(). It always runs on the string in front of the dot, and it always returns a new value — it never changes the original string.

song = "Blinding Lights" loud = song.upper() print(song) # Blinding Lights -- unchanged print(loud) # BLINDING LIGHTS -- a brand new string

That last part matters more than it looks like it should: strings in Python are immutable, meaning once one is created it can never be edited in place. Every string method hands you back a fresh string instead of modifying the one you called it on — if you want to keep the result, you have to store it, usually by reassigning it to a variable.

This is the same str()/int()/float() idea from Variables and Basic Math — those are standalone functions you wrap around a value, str(age). A string method is different only in where it lives: attached to the string itself with a dot, not wrapped around it.

02

Common Problems / Errors

Forgetting the string method result has to be stored: calling .upper() doesn't change the original variable — it hands back a new string that gets thrown away unless you catch it.
song = "faded" song.upper() print(song) # faded -- NOT "FADED", the result was never saved song = song.upper() print(song) # FADED -- correct: reassigned back to song

Trying to edit a string directly

Strings are immutable — you cannot change one character in place. This is a hard error, not a warning.

word = "cat" word[0] = "b" TypeError: 'str' object does not support item assignment

.find() returns -1, not an error

Searching for text that isn't there doesn't crash the program — it quietly returns -1. Forgetting to check for that is a common logic bug, not a crash.

"eggplant".find("z") # -1, not None, not an error
Case matters for every one of these methods and for == comparisons. "Hello" == "hello" is False — if you want a case-blind comparison, run .lower() on both sides first: "Hello".lower() == "hello".lower().
03

Python Code vs. Pseudocode

There isn't really a comparison to make here — and that gap is worth knowing about.

None of this exists in AP CSP pseudocode. The official AP CSP Exam Reference Sheet has no string methods at all — no upper, no lower, no find, nothing. Pseudocode on the exam only ever shows plain values being assigned, compared, and combined with basic arithmetic — the whole idea of a "method attached to a string" is a Python-specific convenience the exam doesn't test.

That means everything on this page is fair game for a Python-based classwork or project, but you will not see .upper() or .find() show up in a pseudocode question on the actual AP exam. If a multiple-choice question needs a string operation, it'll stick to things pseudocode does define — assignment, comparison, and basic list operations.

04

Spotify Examples (5)

Five places a real music app would reach for one of these methods.

.upper()

"NOW PLAYING" banner

status = "now playing" print(status.upper())

Output: NOW PLAYING. A display-only style choice, not a change to the stored data.

.lower()

Building a URL slug

artist = "Billie Eilish" slug = artist.lower()

Output: "billie eilish". Real URLs are usually lowercase, so the app converts before building the link.

.strip()

Cleaning up a search box

query = " drake " clean = query.strip()

Output: "drake". Without this, a search for "drake" with an accidental trailing space might not match anything.

.find() / in

Does the title match the search?

title = "Blinding Lights" "Light" in title

Output: True. This is exactly how a search bar decides which songs to show as you type.

.split()

Splitting "Artist - Song"

track = "The Weeknd - Blinding Lights" parts = track.split(" - ") artist = parts[0] song = parts[1]

parts becomes ['The Weeknd', 'Blinding Lights'] — one string turned into two usable pieces.

A string method never changes the string it's called on — it hands you a new one.Every method on this page follows the same rule: run it, catch what it returns, and store that if you want to keep it. That's the one idea behind all of them.

A whole toolbox comes free with every string — you just have to call it with a dot.

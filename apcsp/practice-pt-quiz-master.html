Practice PT 1: Quiz Master

A math quiz that asks every question in a list, counts the score, and tells the player if they passed. This page shows the finished program, a video plan, the reference sheet, and sample written responses.

00

What We Are Building

Start every Create Task with a plan in words. These four lines are written as comments at the top of the program, and they also give you the story for your video and your written responses.

Plan partThis program
Purposequiz a player on math facts and tell them if they passed
Inputthe player's name and an answer to each question
Outputfeedback on every answer, the score, and a pass or practice message
Functionalityloops through a list of questions, checks each answer, and counts the score
Why this is a strong project: the list really drives the loop, the procedure has two parameters that both matter, and the passing parameter changes the message. That gives you something solid to say for every written prompt.

The Personalized Project Reference

Four segments from your program, with every comment removed. This is exactly what each one looks like.

Procedure (i): the procedure

def run_quiz(name, passing): score = 0 for i in range(len(questions)): guess = input(questions[i] + " ") if guess.lower() == answers[i]: print("Correct!") score = score + 1 else: print("Not quite. The answer is", answers[i]) print(name, "scored", score, "out of", len(questions)) if score >= passing: print("You passed!") else: print("Keep practicing!") return score

Procedure (ii): the call

result = run_quiz(player, 2)

Sample Written Responses

Both the 2026 and the 2025 wording of each prompt, answered about this program. Yours will be about your program, so use these as a model for the shape of a good answer, never to copy.

Written Response 1 (2026): documentation

I would put a comment above run_quiz saying it asks every question in the questions list, counts the correct answers, and returns the score. Another programmer could read it to understand what the loop in run_quiz does without tracing the code.

Why it earns the point: It describes a real comment for a real segment, and says how another programmer (not the user) would use it.

Written Response 1 (2025): output

One output is the line Sam scored 3 out of 3. It shows the functionality because it reports how many of the questions in the list the player answered correctly.

Why it earns the point: It names one real output and ties it to what the program does.

Written Response 2(a) (2026): the loop

The loop stops when the variable i reaches 3, the length of the questions list, because range(len(questions)) only produces 0, 1, and 2.

Why it earns the point: It names the variable and the specific value, and says why it stops.

Written Response 2(a) (2025): the Boolean expression

The Boolean expression is guess.lower() == answers[i]. It is true when the guess is 8 for the first question, because 8 is answers[0].

Why it earns the point: It names the expression, gives a specific value that makes it true, and says why.

Written Response 2(b) (2026): a call that behaves incorrectly

If I call run_quiz("Sam", 0), the procedure prints You passed! even if Sam gets every answer wrong, because a score of 0 is greater than or equal to the passing value of 0.

Why it earns the point: It gives the real arguments, the wrong behavior, and why it comes from those values. The program still runs, so it is a logic error.

Written Response 2(b) (2025): a change that causes an error

A programmer could change >= to <= in the pass check. Then a high score would print Keep practicing! and a low score would print You passed!.

Why it earns the point: It names a specific change and what the procedure does after it, and the program still runs.

Written Response 2(c) (2026): managing complexity

The questions list manages complexity because one loop can ask any number of questions. Without the list I would need a separate variable and a separate copy of the input and if code for every question, so adding a question would mean writing more code.

Why it earns the point: It says what the list lets the program do and what the code would need without it.

Written Response 2(c) (2025): adding new items

If new questions were added to the end of both lists, the loop would not need to change, because range(len(questions)) uses the length of the list, so it grows by itself.

Why it earns the point: It points to the exact code (len(questions)) that makes no change needed.

One finished program gives you an answer for every part.

Practice PT 2: The Shopping List

The same shape as the Color Counter, with a new topic: the program asks for a maximum price and counts how many items on a shopping list cost that much or less. Seeing the pattern twice shows you what stays the same in every Create Task. This page shows the finished program, a video plan, the reference sheet, and sample written responses.

00

What We Are Building

Start every Create Task with a plan in words. These four lines are written as comments at the top of the program, and they also give you the story for your video and your written responses.

Plan partThis program
Purposecount how many items on a shopping list cost no more than the budget the user types
Inputthe maximum price the user types
Outputthe number of items the user can afford
Functionalityloops through a list of prices and counts the ones that are at or under the user's budget
Compare it to the Color Counter: the list is different (prices, not colors), and the if compares with <= instead of ==. Everything else is the same pattern. That is the idea to take to the real task: change the topic, keep the structure.

This is the program you build in the walkthrough. Each colored underline is one requirement, and the arrow runs from its caption to the code.

RequirementWhere it is
Inputinput(...)` for the maximum price
Listprices`, with several items
Student-developed procedurecount_affordable(items, budget)`, two parameters

Watch out: the budget parameter must really change the result. Typing a different maximum price gives a different count, so it does. A parameter the procedure never used would lose the point.

03

The Personalized Project Reference

Four segments from your program, with every comment removed. This is exactly what each one looks like.

Procedure (i): the procedure

def count_affordable(items, budget): count = 0 for item in items: if item <= budget: count = count + 1 return count

Procedure (ii): the call

result = count_affordable(prices, limit)

List (i): where the data is stored

prices = [3, 8, 2, 5, 1, 9]

List (ii): where the list is used

for item in items: if item <= budget: count = count + 1
No comments and no course content. Check every segment for a # before you take the screenshots.
04

Sample Written Responses

Both the 2026 and the 2025 wording of each prompt, answered about this program. Yours will be about your program, so use these as a model for the shape of a good answer, never to copy.

Written Response 1 (2026): documentation

I would put a comment above count_affordable saying it loops through the list of prices and counts how many are at or under the budget. Another programmer could read it to understand the loop and the if without tracing the code.

Why it earns the point: It describes a real comment for a real segment, and says how another programmer would use it.

Written Response 1 (2025): output

One output is the line You can afford: 4 items. It shows the functionality because it reports how many prices in the list are at or under the budget the user typed.

Why it earns the point: It names one real output and ties it to what the program does.

Written Response 2(a) (2026): the loop

The loop stops when the variable item has been every price in the list, so after the sixth price, because a for loop over a list ends when it runs out of items.

Why it earns the point: It names the variable and the point where it stops, and says why.

Written Response 2(a) (2025): the Boolean expression

The Boolean expression is item <= budget. It is true when item is 3 and budget is 5, because 3 is less than or equal to 5.

Why it earns the point: It names the expression, gives a specific value that makes it true, and says why.

Written Response 2(b) (2026): a call that behaves incorrectly

If I call count_affordable(limit, prices) with the arguments swapped, the program stops with an error, because items would be a number and a for loop cannot go through a number.

Why it earns the point: It gives the real call, the wrong behavior, and why.

Written Response 2(b) (2025): a change that causes an error

A programmer could change <= to < in the if statement. Then a price exactly equal to the budget would not be counted, and the count would be too low.

Why it earns the point: It names a specific change and what the procedure does after it.

Written Response 2(c) (2026): managing complexity

The prices list manages complexity because one loop counts the affordable prices in a list of any size. Without it I would need a separate variable and a separate comparison for every price.

Why it earns the point: It says what the list lets the program do and what the code would need without it.

Written Response 2(c) (2025): adding new items

If new prices were added to the end of the list, the procedure would not need to change, because for item in items goes through however many items the list has.

Why it earns the point: It points to the exact code that makes no change needed.

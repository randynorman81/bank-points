Comparison Operators

The Booleans page introduced these six — this page is the deep dive: what they can compare, what breaks, and a shortcut Python allows that most languages don't.

00

Definition

A comparison operator takes two values and produces a boolean. Python has six, and they work on more than just numbers.

OperatorMeaningNumbersStrings
==Equal to5 == 5.0 → True"cat" == "cat" → True
!=Not equal to5 != 6 → True"cat" != "Cat" → True
> / <Greater / less than7 > 2 → True"banana" > "apple" → True
>= / <=At least / at most7 >= 7 → True"a" <= "b" → True

Numbers compare by value — 5 and 5.0 are == even though one's an int and one's a float. Strings compare alphabetically, letter by letter (this is called lexicographic order), and it's case-sensitive: every uppercase letter counts as "smaller" than every lowercase letter, so "Zebra" < "apple" is actually True.

Comparisons happen after the math

Python fully evaluates both sides — running any +, *, //, etc. — before comparing them. Comparison operators sit at the very bottom of the order-of-operations list.

x = 3 result = x + 2 > x * 2 # Python computes: (x + 2) > (x * 2) -> 5 > 6 -> False

Python's shortcut: chaining

Most languages force you to repeat the variable when checking a range (see the Logical Operators page). Python actually allows a shortcut most languages don't: chained comparisons.

The long way (always works)

0 <= volume and volume <= 100

Python's shortcut

0 <= volume <= 100
Both lines do the exact same thing. The chained version only works in Python — if you ever write code in Java or JavaScript, you'll need the and-joined version instead. Either is fine to use here, but know that the chained version is a Python-only convenience, not something you'll see on the language-agnostic parts of the AP exam.
01

Examples

Comparisons plug directly into everything from the last two pages — storing a boolean, or dropping straight into an if.

numbers

Different types, same value

print(5 == 5.0)

Output: True. Python compares the value, not the type.

strings

Case sensitivity

print("Apple" == "apple")

Output: False. Capital A and lowercase a are different characters.

strings

Alphabetical order

print("apple" < "banana")

Output: True. a comes before b, so the whole string does too.

chained

A clean range check

grade = 85 print(80 <= grade < 90)

Output: True. Reads almost exactly like the math-class version.

02

Common Problems / Errors

Comparing incompatible types: Python allows int vs. float, but comparing a number to a string with </> is an error — there's no sensible way to say a number is "less than" a word.
age = 15 print(age > "10") TypeError: '>' not supported between instances of 'int' and 'str'

Assuming string length matters

"z" < "aa" is False — Python compares character by character, not by length. "z" just comes after "a", so it's "bigger" regardless of how long either string is.

= vs ==, again

Still the single most common mistake with comparisons — one equals sign assigns, two compares. If Python throws a SyntaxError on a line with an if, check this first.

Reading input with input() always gives you back a string, even if the user typed a number. input("Age: ") > 18 compares a string to an int and crashes — wrap it in int(...) first: int(input("Age: ")) > 18.

Python Code vs. Pseudocode

The same table from the Booleans page, worth repeating here since this whole page is about these six symbols.

ConceptAP CSP PseudocodePython

Not equal to≠!=

Pseudocode has no chained-comparison shortcut at all — a range check is always written out in full, e.g. IF (0 ≤ volume AND volume ≤ 100). Chaining (0 <= volume <= 100) is purely a Python convenience.
04

Spotify Examples (5)

Five real comparisons, from plain numbers to alphabetical sorting.

chained

Valid volume range

is_valid = 0 <= volume <= 100

One clean line instead of two joined with and.

strings

Sorting artist names

print("Adele" < "Beyoncé")

Output: True — this is exactly how an alphabetical artist list gets sorted under the hood.

case-sensitive

Matching a typed username

print(typed_name == stored_name)

A login that's case-sensitive on purpose — "Alex" and "alex" won't match.

int() conversion

Comparing typed input

age = int(input("Age: ")) is_teen = 13 <= age <= 19

Without int(), this comparison would crash — input() always returns a string.

not equal

Detecting a song change

song_changed = current_song != last_song

Used to decide whether to refresh the "Now Playing" screen.

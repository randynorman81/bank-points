PYTHON NOTES  /  SUBJECT: MAKING CODE BRANCH

If Statements

Where booleans and comparisons actually pay off — the same branching you already did with Karel back in 1.11, now in real Python syntax.

00

Definition

An if statement runs a block of code only when its condition is True. If the condition is False, the entire indented block is skipped — nothing inside it runs at all.

if condition: # this block only runs when condition is True

Two things are non-negotiable: the line ends with a colon (:), and everything inside the block is indented — consistently, usually 4 spaces. Python uses that indentation, not curly braces like { }, to know exactly which lines belong inside the if.

This is the exact same idea from Karel

Back in 1.11, an if in Karel checked something like front_is_blocked() and ran a block only when it was true. Python's version works identically — the only thing that changed is what's allowed inside the condition. Now it's any boolean expression: a comparison, a stored boolean variable, or one combined with and/or/not.

score = 75 if score >= 60: print("You passed")

No else is required. If score >= 60 is False here, the program just moves on — nothing gets printed, and that's completely normal.

Nesting: an if inside an if

An if block can contain another if, indented one level deeper. The inner condition is only even checked if the outer one was already True.

if is_logged_in: if is_admin: print("Welcome, admin")
Nesting works, but two or three levels deep gets hard to read fast. Combining conditions with and (from Logical Operators) is often clearer than nesting: if is_logged_in and is_admin: does the exact same thing as the example above, in one line.

Examples

Every flavor of condition from the last three pages can go directly after if.

comparison

Direct comparison

if age >= 18: print("Adult")

The most common shape — a comparison written right in the condition.

stored boolean

A variable, no comparison

if is_muted: print("Silent")

Works because is_muted is already True or False.

combined

and / or inside the condition

if age >= 13 and age <= 19: print("Teenager")

Everything from Logical Operators drops in directly.

nested

if inside if

if is_playing: if volume == 0: print("Playing muted")

The inner check only happens if the outer one passed.

02

Common Problems / Errors

Missing colon: every if line has to end in :. Leaving it off is an instant syntax error.
if score >= 60 print("Passed") SyntaxError: expected ':'

Inconsistent indentation

Mixing tabs and spaces, or indenting one line 4 spaces and the next 5, throws an IndentationError. Pick one style (4 spaces is standard) and stay consistent the whole file.

= instead of ==

Still the classic. if score = 100: is a SyntaxError — Python won't let a single = sit inside a condition at all.

Code that's supposed to run whether or not the condition was true goes outside the indented block — back at the same indentation as the if itself. If it stays indented, it becomes part of the conditional block by accident and won't run when the condition is False.
03

Python Code vs. Pseudocode

Same core idea, different punctuation for marking the block.

ConceptAP CSP PseudocodePython
Conditional blockIF (condition)
    <block>		if condition:
    <block>
Pseudocode wraps the condition in parentheses and just indents the block underneath, no colon. Python drops the parentheses (though you can add them, they're optional around a condition) and requires the colon instead. On the multiple-choice exam, any indented block under an IF line is exactly what a colon-and-indent block means in Python.

Spotify Examples (5)

Five real one-branch decisions from a music app.

comparison

Low battery warning

Only shown when it's actually relevant.

stored boolean

Ad-free playback

No comparison needed — the flag speaks for itself.

combined

Free-tier skip limit

if not is_premium and skip_count >= 6: block_skip()

Two conditions from Logical Operators, combined in one if.

nested

Offline download check

if is_offline: if song.is_downloaded: play_song()

Only checks whether the song is downloaded if the app is actually offline.

chained comparison

Mid-range volume icon

if 30 <= volume < 70: show_medium_volume_icon()

The chained comparison from the last page, used directly in a condition.

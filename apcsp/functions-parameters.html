Functions and Parameters

A function is a named group of instructions. You write it once, then run it as many times as you like by calling its name. A parameter lets each call hand it different data.

00

Definition

A function (the AP exam calls it a procedure) is a named group of instructions. Defining a function teaches Python the instructions and gives them a name. Calling the function runs them. A parameter is a variable in the definition that receives data, and an argument is the actual value you pass in when you call it.

def greet(name): # define: teach Python. Nothing runs yet. print("Hello,", name) greet("Ana") # call: run it. name is "Ana". greet("Ben") # call again. name is "Ben". # output: # Hello, Ana # Hello, Ben

The parts of a function, labeled

Define, call, parameter, argument

WordWhere it isIn the example
definethe def blockdef greet(name):` teaches Python the job
calla line that uses the name with bracketsgreet("Ana")` runs the job
parameterinside the brackets of the def linename` is the box that receives the data
argumentinside the brackets of the call"Ana"` is the value that goes into the box

When Python reaches a call, it jumps into the function, runs its instructions top to bottom with the parameter holding the argument, and then jumps back to the line right after the call.

Defined, never called

def greet(name): print("Hello,", name) # nothing prints: the function was # defined but nobody called it

A def on its own does nothing visible.

Defined, then called

def greet(name): print("Hello,", name) greet("Ana") # now it runs

The call is what makes the instructions run.

Why bother? If you need the same job in ten places, you write the instructions once. Change them once and every call changes. That is the big exam idea behind procedures: less repeated code, easier to change, easier to read.
01

Examples

The same three-part pattern every time: define it, call it, and give it different arguments.

no parameter

A function that takes nothing

def welcome(): print("Welcome to the game!") welcome() welcome()

Empty brackets mean it needs no data. Calling it twice prints the line twice.

one parameter

Double a number

def double(number): print(number * 2) double(4) # 8 double(10) # 20

number holds 4 on the first call and 10 on the second. One definition, two different results.

string parameter

Shout a word

def shout(word): print(word + "!") shout("go") # go! shout("stop") # stop!

Parameters can hold any kind of value, including text.

variable as argument

Pass a variable

player = "Dee" greet(player) # name is "Dee" # the value inside player is copied into the parameter

The argument can be a variable or any expression. Python works out its value first, then passes it in.

calls in a row

Reuse in action

def bar(length): print(length * "#") bar(3) # ### bar(5) # ##### bar(1) # #

Three calls, three different bars, one definition.

02

Common Problems / Errors

The most common mistake: writing the def and forgetting to call it. If nothing happens, check that a line with the function's name and brackets comes after the definition.

Calling before defining

greet("Ana") def greet(name): print("Hello,", name) # NameError: name 'greet' is not defined

Python reads top to bottom. The function must be defined above the line that calls it.

Wrong number of arguments

def greet(name): print("Hello,", name) greet() # TypeError: missing 1 required argument greet("Ana", "Ben") # TypeError: takes 1 argument but 2 were given

The call must give exactly as many arguments as the definition has parameters.

Body not indented

def greet(name): print("Hello,", name) # IndentationError

Everything inside the function is indented under the def line, and it needs the colon.

A parameter lives inside its function

name only exists while the function runs. Trying to print name on a line outside the function causes a NameError. The value you pass in is copied into the parameter.

Know these words for the exam: a procedure is a named group of instructions. A parameter is a variable in the definition, and an argument is the value given in the call. A call interrupts the normal top-to-bottom flow, runs the procedure, and then continues with the line after the call.
On the exam you usually trace a call: write down which argument goes into which parameter, then follow the instructions with those values.

Define it once, call it many times, and let the parameter carry the data in.

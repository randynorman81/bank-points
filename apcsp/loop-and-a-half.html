PYTHON NOTES  /  SUBJECT: CHECKING THE CONDITION MID-LOOP

Loop and a Half

What to do when you need to run part of the loop body before you can even check whether to stop — a named pattern, not a new keyword.

00

Definition

A regular while loop checks its condition before the body ever runs. Sometimes that doesn't work — you need to do something first (like ask the user a question) before you have anything to check at all. The loop and a half pattern solves this with while True: and a break in the middle.

while True: answer = input("Keep going? (yes/no): ") if answer != "yes": break # ...the rest of the loop body...

while True: is a condition that's always True — on its own, that's an infinite loop. What makes it stop is break: the instant Python runs a break statement, it exits the loop immediately, skipping anything left in the body and continuing with whatever comes after the loop.

Why "and a half"?

The name describes where the check happens: it's not cleanly at the top of the loop (like a normal while) or the bottom — it's somewhere in the middle, after some code has already run once. You get "half a pass" of the loop body before the first real check happens.

break works inside a for loop too, not just while True: — it always means the exact same thing: "stop this loop right now, regardless of its condition."
01

Examples

This pattern shows up constantly with user input — you can't validate an answer you haven't asked for yet.

Can't do this with a plain while

while answer != "quit": answer = input("Command: ") # ERROR: answer is used before # it's ever been created

The condition needs answer to already exist — but it's only created inside the loop.

Loop and a half fixes it

while True: answer = input("Command: ") if answer == "quit": break print("Running:", answer)

Ask first, then decide whether to stop — no variable needs to exist before the loop starts.

A running total, stopped by a sentinel value

A sentinel value is a special input (like -1 or an empty string) that means "stop" rather than being real data. Loop and a half is the standard way to handle one.

total = 0 while True: entry = int(input("Enter a number (-1 to stop): ")) if entry == -1: break total = total + entry print("Total:", total)
02

Common Problems / Errors

Forgetting break entirely: while True: with no break anywhere inside it is a guaranteed infinite loop — there's no other way out.

break in the wrong place

If break sits before code that was supposed to run on every pass, that code never executes on the final, stopping pass. Where exactly break goes relative to the rest of the body matters.

Confusing break with continue

break exits the loop completely. continue (not covered in depth here) only skips the rest of the current pass and goes back to re-checking the condition — a very different thing.

Code placed after break but still inside the loop body never runs on the pass where break fires — Python exits immediately. If something needs to happen even when stopping, put it before the break, or after the loop entirely.
03

Python Code vs. Pseudocode

This pattern is a real Python/programming technique, not a pseudocode block on its own.

The AP Reference Sheet's pseudocode has REPEAT UNTIL and REPEAT n TIMES, but no direct equivalent of "loop forever, then break out partway through." On the exam, this kind of logic is usually just described in words or shown as a flowchart rather than written as a specific pseudocode block — "loop and a half" is a real Python coding pattern for your Create Performance Task, more than something to memorize a pseudocode form for.
04

Spotify Examples (5)

Five real "ask, then decide" moments from a music app.

01

Search until a result is picked

while True: query = input("Search: ") results = search(query) if len(results) > 0: break play(results[0])

Keeps re-searching until at least one result comes back.

02

Building a playlist, one song at a time

playlist = [] while True: song = input("Add song (blank to finish): ") if song == "": break playlist.append(song)

An empty string is the sentinel value that ends the loop.

03

Password re-entry

while True: password = input("Password: ") if check_password(password): break print("Try again.")

Has to ask at least once before there's anything to check — a perfect loop-and-a-half case.

04

Skipping until a likeable song

while True: song = get_next_song() if song.rating >= 3: break skip(song)

Keeps skipping low-rated songs until a good one is found.

05

Volume adjustment loop

while True: key = get_key_press() if key == "Enter": break adjust_volume(key)

Reacts to key presses indefinitely, until Enter confirms the final volume.

while True: plus break means "run first, decide after."Reach for this pattern any time the very first check needs data that doesn't exist until the loop has already started.

while True: + break covers the loops a plain while can't even start.

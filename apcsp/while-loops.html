While Loops

Booleans control this loop directly — it keeps running for as long as its condition stays True, with no built-in counter doing the work for you.

00

Definition

A while loop re-checks a boolean condition before every single pass, and keeps running the block as long as it's True. Unlike a for loop, it has no idea in advance how many times it'll run — that depends entirely on when the condition becomes False.

count = 0 while count < 5: print(count) count = count + 1 # output: 0, 1, 2, 3, 4

This is exactly the boolean-in-a-condition idea from the Booleans page, just checked over and over instead of once. Three things have to be true for this to behave correctly: count exists before the loop starts, the condition uses it, and something inside the loop eventually changes it.

The danger: forgetting to change the condition

A for loop's range() guarantees it'll eventually stop. A while loop guarantees nothing — if nothing inside the loop ever makes the condition False, it runs forever. This is called an infinite loop, and it's the single most common while-loop bug.

Infinite loop

count = 0 while count < 5: print(count) # forgot to change count!

Correctly updates the condition

count = 0 while count < 5: print(count) count = count + 1
If a program ever seems to freeze or a "Loading…" spinner never stops, an infinite loop is one of the first things to suspect. In an online editor, there's usually a stop/reset button for exactly this reason.
01

Examples

While loops shine whenever the stopping point isn't known ahead of time.

boolean flag

Looping until a flag flips

is_running = True while is_running: # ...do something... is_running = check_if_done()

No counter at all — the loop's entire lifespan is controlled by one boolean.

user input

Keep asking until valid

age = int(input("Age: ")) while age < 0: print("Try again.") age = int(input("Age: "))

Keeps re-prompting for as long as the entered value is invalid.

combined condition

and / or inside the condition

while lives > 0 and not game_over: play_round()

Everything from Logical Operators works here too — the loop keeps going only while both hold.

unknown count

Halving until small enough

value = 200 steps = 0 while value > 1: value = value / 2 steps = steps + 1

There's no way to know steps in advance without actually running the loop — a for loop couldn't do this.

02

Common Problems / Errors

The infinite loop: by far the most common while-loop bug. Always double check that something inside the loop body actually moves the condition toward becoming False.

Off-by-one on the boundary

count = 0 while count <= 5: # <= instead of < print(count) count = count + 1 # prints 0 through 5 -- six times, not five

The exact same < vs. <= boundary mistake that trips people up with range().

Condition checked, never true from the start

If the condition is already False the very first time it's checked, the loop body never runs at all — not even once. That's correct behavior, not a bug, but it's easy to mistake for "the loop is broken."

03

Python Code vs. Pseudocode

Pseudocode calls this a REPEAT UNTIL — watch the direction of the condition closely.

ConceptAP CSP PseudocodePython
Loop while trueREPEAT UNTIL (condition)
    <block>		while not (condition):
    <block>
This is the one that catches people: pseudocode's REPEAT UNTIL (condition) loops until the condition becomes true — the exact opposite direction of Python's while, which loops while it's true. Translating pseudocode's REPEAT UNTIL x > 10 into Python is while x <= 10:, not while x > 10:.
04

Spotify Examples (5)

Five real "keep going until…" moments from a music app.

boolean flag

Playing until the queue is empty

while len(queue) > 0: play(queue.pop(0))

The loop's own actions shrink the queue until the condition finally fails.

user input

Login retry

attempts = 0 while not login_success and attempts < 3: login_success = try_login() attempts = attempts + 1

Two conditions from Logical Operators, stopping the retry loop either way.

fade effect

Fading the volume down

while volume > 0: volume = volume - 1 set_volume(volume)

Runs a different number of times depending on the starting volume — a for loop couldn't know that count in advance.

buffering

Waiting for enough buffer

while buffered_seconds < 5: buffer_more()

Keeps buffering for as long as there isn't enough loaded to start playback smoothly.

while doesn't count. It just keeps checking.Use it the moment "how many times" depends on something that can only be known while the program is actually running.

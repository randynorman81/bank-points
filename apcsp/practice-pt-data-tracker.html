01

The Finished Program, Every Requirement Labeled

This is the program you build in the walkthrough.

# PURPOSE: track daily steps and report how many days reached a goal # INPUT: the daily step goal the user types # OUTPUT: the number of days at the goal and the average steps # FUNCTIONALITY: loops through a list of daily steps and counts the days that reach the goal goal = int(input("Daily step goal: ")) steps = [4200, 8100, 6500, 9800, 7300] def days_at_goal(data, target): count = 0 for day in data: if day >= target: count = count + 1 return count def average(data): total = 0 for day in data: total = total + day return total / len(data) print("Days at goal:", days_at_goal(steps, goal)) print("Average steps:", average(steps))
RequirementWhere it is
Inputinput(...) for the goal
Liststeps, with several items
Student-developed proceduredays_at_goal(data, target), two parameters
Sequencing, selection, iterationcount = 0, the if, and the for, all inside days_at_goal
Use of the listfor day in data: reads every day
Calldays_at_goal(steps, goal), two arguments
Outputthe two print lines
The target parameter must really change the result. Typing a different goal gives a different count, so it does. A parameter the procedure never used would lose the point.

The Personalized Project Reference

Four segments from your program, with every comment removed.

Procedure (i): the procedure

def days_at_goal(data, target): count = 0 for day in data: if day >= target: count = count + 1 return count

Procedure (ii): the call

print("Days at goal:", days_at_goal(steps, goal))

List (i): where the data is stored

steps = [4200, 8100, 6500, 9800, 7300]

List (ii): where the list is used

for day in data: if day >= target: count = count + 1
No comments and no course words in the reference. Check every segment for a # before you take the screenshots.
04

Sample Written Responses

Both wordings of each prompt, answered about this program. Use them as a model for the shape of a good answer, never to copy.

Written Response 1 (2026): documentation

I would put a comment above days_at_goal saying it loops through the list of daily steps and counts how many days are at or above the target. Another programmer could read it to understand the loop and the if without tracing the code.

Why it earns the point: It describes a real comment for a real segment, and says how another programmer would use it.

Written Response 1 (2025): output

One output is the line Days at goal: 3. It shows the functionality because it reports how many days in the list reached the goal the user typed.

Why it earns the point: It names one real output and ties it to what the program does.

Written Response 2(a) (2026): the loop

The loop stops when the variable day has been every value in steps, so after the fifth day, because a for loop over a list ends when it runs out of items.

Why it earns the point: It names the variable and the point where it stops, and says why.

Written Response 2(a) (2025): the Boolean expression

The Boolean expression is day >= target. It is true when day is 8100 and target is 7000, because 8100 is greater than or equal to 7000.

Why it earns the point: It names the expression, gives specific values that make it true, and says why.

Written Response 2(b) (2026): a call that behaves incorrectly

If I call days_at_goal(goal, steps) with the arguments swapped, the program stops with an error, because data would be a number and a for loop cannot go through a number.

Why it earns the point: It gives the real call, the wrong behavior, and why.

Written Response 2(b) (2025): a change that causes an error

A programmer could change >= to > in the if statement. Then a day exactly equal to the goal would not be counted, and the count would be too low.

Why it earns the point: It names a specific change and what the procedure does afterward.

Written Response 2(c): managing complexity

The steps list manages complexity because one loop can count and average any number of days. Without the list I would need a separate variable for every day and a separate if for each one, and I would have to rewrite the code whenever a day was added.

Why it earns the point: It says how the list helps and what the code would need without it.

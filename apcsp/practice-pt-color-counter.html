Practice PT 1: Color Counter

The simplest program that still meets every Create Task requirement: it asks for a color and counts how many times that color is in a list. This page shows the finished program, a video plan, the reference sheet, and sample written responses.

00

What We Are Building

Start every Create Task with a plan in words. These four lines are written as comments at the top of the program, and they also give you the story for your video and your written responses.

Plan partThis program
Purposecount how many times a color the user picks appears in a list of colors
Inputthe color the user types
Outputthe number of matches
Functionalityloops through a list of colors and counts the ones that match the user's color
Why this is enough: the list really drives the loop, the target parameter changes the answer, and the if decides what is counted. Nothing extra is needed, and everything you must explain on exam day is right here.

03

The Personalized Project Reference

Four segments from your program, with every comment removed. This is exactly what each one looks like.

Procedure (i): the procedure

def count_matches(items, target): count = 0 for item in items: if item == target: count = count + 1 return count

Procedure (ii): the call

result = count_matches(colors, choice)

List (i): where the data is stored

colors = ["red", "blue", "red", "green", "red"]

List (ii): where the list is used

for item in items: if item == target: count = count + 1
No comments and no course content. Check every segment for a # before you take the screenshots.

Sample Written Responses

Both the 2026 and the 2025 wording of each prompt, answered about this program. Yours will be about your program, so use these as a model for the shape of a good answer, never to copy.

Written Response 1 (2026): documentation

I would put a comment above count_matches saying it loops through the list and counts how many items equal the target color. Another programmer could read it to understand the loop and the if without tracing the code.

Why it earns the point: It describes a real comment for a real segment, and says how another programmer would use it.

Written Response 1 (2025): output

One output is the line Matches: 3. It shows the functionality because it reports how many colors in the list equal the color the user typed.

Why it earns the point: It names one real output and ties it to what the program does.

Written Response 2(a) (2026): the loop

The loop stops when the variable item has been every color in the list, so after the fifth color, because a for loop over a list ends when it runs out of items.

Why it earns the point: It names the variable and the point where it stops, and says why.

Written Response 2(a) (2025): the Boolean expression

The Boolean expression is item == target. It is true when item is red and target is red, because they are the same text.

Why it earns the point: It names the expression, gives a specific value that makes it true, and says why.

Written Response 2(b) (2026): a call that behaves incorrectly

If I type Red with a capital R, count_matches(colors, "Red") returns 0 even though red is in the list, because Red is not equal to red.

Why it earns the point: It gives the real argument, the wrong behavior, and why. The program still runs, so it is a logic error.

Written Response 2(b) (2025): a change that causes an error

A programmer could change == to != in the if statement. Then the procedure would count every color that is not the target, and the count would be wrong.

Why it earns the point: It names a specific change and what the procedure does after it.

Written Response 2(c) (2026): managing complexity

The colors list manages complexity because one loop counts matches in any number of colors. Without it I would need a separate variable and a separate comparison for every color.

Why it earns the point: It says what the list lets the program do and what the code would need without it.

Written Response 2(c) (2025): adding new items

If new colors were added to the end of the list, the procedure would not need to change, because for item in items goes through however many items the list has.

Why it earns the point: It points to the exact code that makes no change needed.

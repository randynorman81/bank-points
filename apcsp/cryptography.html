Cryptography

When you send a password or a bank number over the internet, it passes through many computers you do not control. Cryptography scrambles the message so only the right person can read it.

00

The Basic Words

Encryption turns a readable message into scrambled nonsense, and decryption turns it back.

WordMeaning
plaintextthe original, readable message
ciphertextthe scrambled message
encryptionplaintext to ciphertext
decryptionciphertext back to plaintext
cipherthe method (the algorithm) used to scramble
keythe secret value that controls the scrambling
01

The Caesar Cipher

One of the oldest ciphers: shift every letter a fixed number of places down the alphabet. The shift is the key.

Try it: Caesar cipher

Pick a key (the shift). Switch between encrypting and decrypting.

Key (shift):
def encrypt(text, shift): result = "" for ch in text: if ch.isalpha(): base = ord("A") if ch.isupper() else ord("a") result = result + chr((ord(ch) - base + shift) % 26 + base) else: result = result + ch return result print(encrypt("HELLO", 3)) # KHOOR print(encrypt("xyz", 3)) # abc (it wraps around)

ord(ch) - base turns the letter into a position 0 to 25. Adding the shift moves it, and % 26 makes it wrap around from Z back to A. chr(... + base) turns the position back into a letter. Spaces and punctuation are left alone.

DecryptingTo decrypt, shift backwards by the same key: encrypt(cipher, -3). The sender and receiver must both know the key, 3.
The Caesar cipher is weak. There are only 25 possible keys, so a computer (or a patient person) can try all of them in an instant. This is called a brute-force attack.
02

Symmetric Encryption

In symmetric encryption, the same key encrypts and decrypts. The Caesar cipher is symmetric.

The big problem with symmetric keys: how do two people agree on the key if they have never met? Sending the key over the internet could let a spy steal the key too.
03

Public Key Encryption

Public key (asymmetric) encryption solves the key-sharing problem with two different keys that belong together.

KeyWho has itWhat it does
Public keyeveryone can see itencrypts a message to its owner
Private keyonly the owner keeps it secretdecrypts that message

Click through: Ana sends Ben a secret

Ben makes a pair of keys: a public key and a private key. He keeps the private key secret.

Ben posts his public key where anyone, including Ana, can see it. A spy can see it too, and that is fine.

Ana encrypts her message with Ben's public key and sends the ciphertext. The spy has the ciphertext and the public key, but cannot read the message.

Only Ben's private key can decrypt it. Only Ben can read the message, even though the public key was out in the open.

This works because the math is easy to do one way but extremely slow to undo without the private key. Breaking it would take an unreasonable amount of time (remember Unit 7).

04

Trust on the Web

You use these ideas every time you see https and the lock in your browser.

IdeaWhat it does
HTTPS / TLSencrypts the data between your browser and a website, using public key encryption to agree on a secret
Digital certificateproves that a public key really belongs to that website
Certificate authoritya trusted organization that issues certificates
Longer keysmean more possible keys, so brute force takes much longer
Encryption protects data in transit, but it cannot protect you if you hand your password to a fake website. The certificate check helps you notice that.
05

On the AP Exam

Expect questions about which kind of encryption fits a situation and why it is safe.

  • Encryption scrambles data, and decryption unscrambles it.
  • Symmetric: one shared key. Public key: a public key encrypts and a private key decrypts.
  • Public key encryption lets strangers communicate securely without sharing a secret first.
  • A cipher with few possible keys (like Caesar) is easy to break by trying them all.
  • Certificate authorities issue certificates that verify who owns a public key.

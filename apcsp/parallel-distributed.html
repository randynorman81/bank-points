Sequential and Parallel

A normal program runs sequentially: one instruction after another, in order. Parallel computing splits a job into parts and runs several parts at the same time, each on its own processor. A distributed system does it with many separate computers connected by a network.

01

Speedup

Speedup measures how much faster the parallel version is: sequential time ÷ parallel time.

Example: A job takes 120 seconds sequentially and 40 seconds in parallel. Speedup = 120 ÷ 40 = 3. It runs three times as fast.

Try it: share the work between processors

Each number is how many seconds a task takes. Choose how many processors you have. Each task goes to the processor that frees up first.

Try 40, 30, 60, 50, 20 with 1, 2, 3, then 5 processors. At some point adding processors stops helping. The longest task sets the minimum time.
02

What Limits Parallel Computing?

Splitting the work does not always make it faster.

1

Tasks that must wait

If task B needs the result of task A, B cannot start until A is done. Those tasks stay sequential.

2

The longest path

The whole job takes at least as long as the longest chain of tasks that depend on each other.

3

Overhead

Splitting the work, moving data, and combining the results all take time. Too many tiny pieces can be slower.

Worked example: Task A takes 30 s and task B takes 30 s, and they are independent. Task C takes 20 s and needs both A and B. Sequentially: 30 + 30 + 20 = 80 s. With 2 processors, A and B run together (30 s), then C (20 s): 50 s. Speedup = 80 ÷ 50 = 1.6.
03

Distributed Computing

A distributed computing system uses multiple devices, often far apart, to solve one problem. Projects like Folding@home ask volunteers to donate spare computer time to study proteins. Companies do the same with huge data centers.

Benefits

Can solve problems too big for one computer. Uses many cheap machines. If one machine fails, the others keep going (fault tolerance).

Challenges

Computers must coordinate over a network, which is slower than one computer's memory. Results must be combined. Security and trust matter.

Check yourself

Answer each one. You see why right away, so read the explanation even when you are right.

A job takes 100 seconds on one processor and 40 seconds when run in parallel. What is the speedup?
Speedup = sequential ÷ parallel = 100 ÷ 40 = 2.5.
Tasks of 20 s and 30 s are independent. How long do they take on two processors?
Both run at the same time, so the time is set by the longer task: 30 seconds. (Sequentially it would be 50.)
Which is most likely to prevent a program from being sped up much by parallel computing?
Tasks that must wait for each other must run in order, which means a long sequential path.
Which is an example of distributed computing?
Distributed computing spreads one problem across many computers connected by a network.
AP

On the AP Exam

These are the ideas the exam asks about. Be ready to explain each one in your own words.

  • Sequential runs one step at a time. Parallel runs parts at the same time. Distributed uses many computers.
  • Speedup = sequential time ÷ parallel time.
  • The parallel time is set by the longest chain of tasks that depend on each other.
  • Parallel and distributed computing can solve bigger problems faster, but not every program can be sped up, and there is overhead.
  • Distributed systems can keep working if one part fails (fault tolerance).

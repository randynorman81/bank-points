Practice PT 2: Story Generator

This practice task opens later in the year, after Unit 7. A program that builds a short story from lists of places and actions, in a scary or happy mood. This page shows the finished program, a video plan, the reference sheet, and sample written responses.

00

What We Are Building

This project uses its lists in a new way: the remainder operator % lets the story be longer than the lists. That is great material for the managing complexity prompt.

Plan partThis program
Purposetell a short story about a hero in the mood the player picks
Inputthe hero's name, a mood of scary or happy, and how many scenes to tell
Outputone line for every scene and a message with the number of scenes told
Functionalityloops through places and actions, and picks a scary or happy ending for each scene
Why this is a strong project: the loop is controlled by a parameter (scenes), the list index uses % so it can never run out, and mood changes the output. Every written prompt has something clear to point at.

03

The Personalized Project Reference

Four segments from your program, with every comment removed. This is exactly what each one looks like.

Procedure (i): the procedure

def tell_story(hero, mood, scenes): for i in range(scenes): place = places[i % len(places)] action = actions[i % len(actions)] if mood == "scary": print(hero, "was in", place, "and", action, "and felt afraid.") else: print(hero, "was in", place, "and", action, "and felt happy.") print("The end of the story.") return scenes

Procedure (ii): the call

total = tell_story(hero, mood, count)

List (i): where the data is stored

places = ["a dark forest", "a quiet village", "an old castle"] actions = ["found a map", "met a stranger", "heard a loud noise"]

List (ii): where the list is used

place = places[i % len(places)] action = actions[i % len(actions)]
No comments and no course content. Check every segment for a # before you take the screenshots.
04

Sample Written Responses

Both the 2026 and the 2025 wording of each prompt, answered about this program. Yours will be about your program, so use these as a model for the shape of a good answer, never to copy.

Written Response 1 (2026): documentation

I would put a comment above tell_story saying it prints one scene for every number up to scenes, picks a place and an action from two lists, and ends each scene by the mood. Another programmer could read it to understand the loop without tracing the code.

Why it earns the point: It describes a real comment for a real segment and says how another programmer would use it.

Written Response 1 (2025): output

One output is the line Ana was in a dark forest and found a map and felt afraid. It shows the functionality because it uses the hero, a place and an action from the lists, and the mood the player chose.

Why it earns the point: It names one real output and ties it to what the program does.

Written Response 2(a) (2026): the loop

The loop stops when the variable i reaches the value of scenes, for example 4, because range(scenes) only produces 0, 1, 2, and 3.

Why it earns the point: It names the variable and a specific value, and says why it stops.

Written Response 2(a) (2025): the Boolean expression

The Boolean expression is mood == "scary". It is true when mood holds the text scary, so the scene ends with felt afraid.

Why it earns the point: It names the expression, a specific value that makes it true, and why.

Written Response 2(b) (2026): a call that behaves incorrectly

If I call tell_story("Ana", "Scary", 2), the procedure tells a happy story instead of a scary one, because "Scary" with a capital S is not equal to "scary" in the if statement.

Why it earns the point: It gives real arguments, the wrong behavior, and why. The program still runs, so it is a logic error.

Written Response 2(b) (2025): a change that causes an error

A programmer could change == to != in the if statement. Then a scary mood would print the happy ending and a happy mood would print the scary one.

Why it earns the point: It names a specific change and what the procedure does after it.

Written Response 2(c) (2026): managing complexity

The places list manages complexity because one loop can use any number of places by wrapping around with %. Without the list I would need a separate variable and a separate if statement for every place.

Why it earns the point: It says what the list lets the program do and what the code would need without it.

Written Response 2(c) (2025): adding new items

If new places were added to the end of the places list, the code would not need to change, because i % len(places) uses the length of the list.

Why it earns the point: It points to the exact code that makes no change needed.

A loop controlled by a parameter plus a list that wraps around is a strong combination.

Graphics

CodeHS's Python graphics library — how to size a canvas, place a shape on it, and ask that shape for its own width, height, or radius. Everything here matches Unit 3: Programming with Python.

00

Definition

Before you can draw anything, you need a canvas — the drawing surface itself. Every shape you place afterward is positioned relative to it, so it comes first, every time.

# Set the canvas to 400 wide by 300 tall set_size(400, 300) # Ask the canvas how big it currently is canvas_width = get_width() canvas_height = get_height()

Its coordinate system is flipped from ordinary math: (0, 0) is the top-left corner, x increases moving right, and y increases moving down — not up.

Called by themselves like this, get_width() and get_height() aren't methods on a shape — they return the canvas's current size. Every shape has its own get_width()/get_height()/get_radius() too, called on the shape instead once one exists.

Now, a shape

Once a canvas exists, CodeHS's graphics library draws shapes as objects on top of it. You create a shape, tell it where to go, and add() it to the screen so it actually shows up. Nothing appears until you add it.

circle = Circle(50) # create a circle with radius 50 circle.set_position(100, 100) # place it circle.set_color(Color.blue) # color it add(circle) # now it actually shows up

02

Common Problems / Errors

The #1 mistake: creating and positioning a shape, then never calling add(shape). The shape exists in memory, but nothing shows up on screen — no error, just a blank canvas.

Wrong shape reference

Calling add(circle) when you meant a different variable name silently adds the wrong (or an empty) object. Double-check the variable name matches what you created.

Flipped y-axis surprise

Increasing y moves a shape down the screen, not up — the opposite of a normal math graph. A shape you expect "higher" needs a smaller y value.

Circle and Rectangle don't agree on what set_position(x, y) means: Circle positions its center, Rectangle positions its top-left corner. Mixing that up is the single most common graphics bug on this page — see each shape's own notes for the exact rule.
03

Python Code vs. Pseudocode

Short answer here: there isn't one. Graphics doesn't appear anywhere in the official AP CSP Exam Reference Sheet.

The multiple-choice exam's pseudocode covers assignment, display, input, math, lists, conditionals, loops, and procedures — general programming ideas that work no matter what language you use. Drawing shapes on a canvas is specific to whatever graphics library your class happens to use, so it was never going to be part of a language-agnostic pseudocode. Circle(), Rectangle(), get_width(), and everything else on this page are real skills for your Create Performance Task and CodeHS coursework — just don't expect any of it on the multiple-choice exam.

Spotify Examples (5)

Five pieces of a real "Now Playing" screen — each one built from a canvas call or a shape call from this page. The Circle and Rectangle pages go deeper on each.

01 · Canvas

Sizing the screen

set_size(400, 250)

Every shape after this is placed relative to a 400×250 canvas.

02 · Rectangle

Album art

art = Rectangle(80, 80) art.set_position(20, 20)

A square album cover in the corner — a Rectangle with matching sides.

03 · Circle

The play button

play_btn = Circle(20) x = get_width() / 2 play_btn.set_position(x, 200)

Centered horizontally using the canvas's own width.

04 · Rectangle

The progress bar

bar = Rectangle(get_width() - 40, 6) bar.set_position(20, 180)

Its width is calculated from the canvas's width, so it always spans edge to edge.

05 · Circle

The volume dial

dial = Circle(12) dial.set_position(get_width() - 30, 30)

Positioned relative to the right edge of whatever size canvas is running.

Every position on this screen is written in terms of the canvas's own size, not a fixed number.That's the entire point of get_width() and get_height() — the layout still works correctly even if you resize the canvas later.

Mouse Events

How to make a shape react when the user clicks the canvas — one function, one rule about parentheses, and every shape trick from the Graphics pages becomes interactive.

00

Definition

A mouse click event lets your program run a function every time the user clicks anywhere on the canvas. You write a function that takes the click's x and y position, then register it with add_mouse_click_handler().

# General format def callback(x, y): # do something with the click position add_mouse_click_handler(callback)

The function you write — here called callback, though you can name it anything — is called your handler. You never call it yourself; the canvas calls it for you, automatically, every time a click happens.

What do x and y actually mean?

x and y in def draw_circle(x, y): are parameters — empty slots in the function's parentheses that get filled in with real values every time the function runs. You never fill them in yourself here. The instant the user clicks, the canvas calls your function for you and drops in the exact pixel position of that click.

def draw_circle(x, y): # x = how far right the click was, in pixels from the left edge # y = how far down the click was, in pixels from the top edge circle = Circle(10) circle.set_position(x, y) add(circle)

Click near the top-left of the canvas, and x and y will both be small numbers. Click near the bottom-right, and they'll both be large. You didn't type those numbers anywhere — the canvas measured the click and handed them to your function through x and y.

You can name these parameters anything — def draw_circle(mouse_x, mouse_y): would work exactly the same way. x and y are just the conventional names, because that's literally what values they'll always hold: a click's horizontal and vertical position.

Dot notation: circle.set_position(x, y)

The dot in circle.set_position(x, y) means "tell this specific object to do something." Everything before the dot is which object you're talking to; everything after the dot is the method — an action that object knows how to perform.

With a dot — a method

circle.set_position(x, y) belongs to one specific circle. It only affects circle — nothing else on the canvas moves.

No dot — a plain function

add(circle) isn't tied to any one object. Instead, you hand the circle to it as an argument, the same way you'd pass a number to str().

Read circle.set_position(x, y) left to right like a sentence: "circle, set your position to (x, y)." If your program had two circles, circle_one.set_position(...) and circle_two.set_position(...) would each move only the one named before its own dot — never both at once. That's the whole point of the dot: it says exactly which object the instruction is for.

Notice add_mouse_click_handler(callback) has no parentheses after callback. You're handing over the function itself, not the result of calling it — the canvas will do the calling, later, every time it needs to.
01

Examples

The canvas still has to exist before any of this works — set it up first, exactly like every other Graphics page.

set_size(400, 300) # Create a circle with a radius of 10, centered at the click def make_circle(x, y): circle = Circle(10) circle.set_position(x, y) add(circle) add_mouse_click_handler(make_circle)

This is the library's own official example: a new circle appears at whatever point you click, every single time.

Moving an existing shape to the click

The handler doesn't have to create something new — it can just as easily move a shape that already exists:

dial = Circle(12) dial.set_position(200, 150) add(dial) def move_dial(x, y): dial.set_position(x, y) # just reposition it -- no "global" needed add_mouse_click_handler(move_dial)
Calling a method on dial (like set_position()) works inside the handler with no extra setup, because you're not reassigning the variable dial itself — just changing something about the object it already points to.
02

Common Problems / Errors

Adding parentheses by accident: add_mouse_click_handler(make_circle()) calls make_circle immediately — once, right then, and almost certainly with the wrong number of arguments — instead of registering it to run later on every click.
add_mouse_click_handler(make_circle()) TypeError: make_circle() missing 2 required positional arguments: 'x' and 'y'

Wrong parameter count

def callback(): with no parameters will crash the moment a click happens — the canvas always passes x and y to your handler, whether you use them or not.

Reassigning a variable inside the handler

Unlike calling a method, reassigning a variable declared outside the function (like a click counter) needs the global keyword — see below.

click_count = 0 def count_clicks(x, y): click_count = click_count + 1 # fails without "global" print(click_count) add_mouse_click_handler(count_clicks) UnboundLocalError: local variable 'click_count' referenced before assignment
The fix: add global click_count as the first line inside the function. Python treats any variable you assign to inside a function as local by default — global tells it "no, use the one from outside."
03

Python Code vs. Pseudocode

Same answer as the rest of the Graphics section: mouse events aren't part of the official AP CSP pseudocode at all.

The multiple-choice exam's pseudocode has no concept of "the user clicked here" — it only reacts to values you already have, like INPUT(). Responding to a live click in real time is a graphics-library-specific skill, specific to whichever library your class happens to use. add_mouse_click_handler() is real code for your Create Performance Task, not something you'll see written as pseudocode.
04

Spotify Examples (5)

Five click interactions from a real music app, all built on the exact same handler pattern.

01

Toggling play / pause

is_playing = False def toggle_play(x, y): global is_playing is_playing = not is_playing if is_playing: play_btn.set_color(Color.green) else: play_btn.set_color(Color.red) add_mouse_click_handler(toggle_play)

A click flips a boolean and recolors the button to match.

02

Seeking the progress bar

def seek(x, y): marker.set_position(x, 180) add_mouse_click_handler(seek)

The marker jumps straight to wherever the user clicked along the bar.

03

Adding a song to the queue

def add_to_queue(x, y): song = Rectangle(60, 60) song.set_position(x, y) add(song) add_mouse_click_handler(add_to_queue)

Every click drops a new square "song tile" right where you clicked.

04

Counting skips

skip_count = 0 def count_skips(x, y): global skip_count skip_count = skip_count + 1 print("Skipped " + str(skip_count) + " times") add_mouse_click_handler(count_skips)

Needs global — the count is being reassigned, not just read.

05

Adjusting the volume dial

def set_volume(x, y): dial.set_position(get_width() - 30, y) add_mouse_click_handler(set_volume)

Only the y-coordinate of the click is used — the dial always stays pinned to the right edge.

Every click handler is the same shape: a function that takes x and y, and a single line registering it.What changes is only what you do inside the function — move something, recolor something, count something, or create something new.

One handler function. No parentheses when you register it. The canvas does the rest.

Every interactive graphics program comes down to writing what should happen, then handing that function over and stepping back.

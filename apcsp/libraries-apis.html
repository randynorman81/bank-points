Libraries and APIs

A library is a collection of ready-made procedures. An API is the set of instructions for how to use them. You do not need to know how they work inside, only how to call them.

00

Definition

A library is a collection of procedures that other programmers wrote so you can reuse them. An API (application program interface) is the specification of those procedures: their names, the parameters they take, and what they return. The documentation for the API is how you find out how to use it.

import math # load a library print(math.sqrt(16)) # 4.0 the library does the work print(abs(-7)) # 7 abs is built into Python print(max(3, 9, 5)) # 9

What documentation tells you

Documentation partWhat it tells youExample
Namewhat to callsqrt
Parameterswhat to pass in, and in what orderone number
Returnswhat comes backthe square root, as a decimal
What it doesthe behavior, in plain wordsfinds the number that multiplied by itself gives the input

You call a library procedure exactly like one you wrote yourself: use the name and give the arguments. You cannot see the instructions inside, and you do not need to.

Why libraries matter on the exam: they make big programs easier to build because you reuse tested code instead of rewriting it. The documentation is necessary to know what a procedure does and how to call it correctly.
01

Examples

Each of these is a procedure someone else already wrote. You only need the name, the arguments, and what it returns.

random library

A random number

import random roll = random.randint(1, 6) # a whole number from 1 to 6 print(roll)

Same idea as the exam's RANDOM(1, 6). The library picks the number. You only call it.

math library

Square root

import math print(math.sqrt(25)) # 5.0 print(math.sqrt(2)) # 1.4142135623730951

sqrt takes one number and returns a decimal. You never wrote the instructions inside it.

built-in

Python's own procedures

print(len("robot")) # 5 print(round(3.67)) # 4 print(min(4, 2, 8)) # 2

len, round, min, and max are part of Python itself, ready to call without an import.

calling it right

Use the documentation

# Documentation: # clamp(value, low, high) returns value, but no smaller # than low and no bigger than high # clamp(15, 0, 10) -> 10 # clamp(-3, 0, 10) -> 0 # clamp(7, 0, 10) -> 7

The documentation says the order is value, low, high. Reading it first tells you what to pass and what comes back.

combine them

Procedures working together

import random sides = 6 roll = random.randint(1, sides) print("Rolled", roll, "out of", sides)

A real program uses library procedures and your own together.

02

Common Problems / Errors

Read before you call. Most mistakes with a library come from not checking the order of the parameters or what the procedure returns.

Forgetting the import

print(math.sqrt(9)) # NameError: name 'math' is not defined

Add import math at the top before you use anything from that library.

Arguments in the wrong order

# documentation: draw(x, y, size) draw(50, 10, 20) # x=50, y=10, size=20 ... is that what you meant?

The documentation sets the order. Swapping arguments gives a different result.

You do not need the inside

Do not try to work out how random.randint picks its number. For the exam you only need to know what it does: its parameters and its result.

A library can be new to you

On the exam you may see documentation for a procedure you have never heard of. Treat it like any other: read the parameters and what it returns, then use it.

03

Python Code vs. Pseudocode

The exam has no import. It describes a library procedure in words or as a procedure heading and asks you to use it correctly.

ConceptAP CSP PseudocodePython
Random whole numberRANDOM(a, b)random.randint(a, b)
Call a library procedureresult ← getArea(width, height)result = get_area(width, height)
Use documentationthe question lists what the procedure takes and returnsthe library's documentation page
What the exam asks: which call uses the API correctly, what a call returns, and why using a library is helpful. Documentation matters because without it you cannot tell what the procedure does or how to call it.

A library is code you reuse. An API and its documentation tell you how to call it.

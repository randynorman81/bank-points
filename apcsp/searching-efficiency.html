Searching and Efficiency

Two algorithms for finding an item in a list, and a way to judge whether an algorithm is fast enough. The exam asks you to trace them and to compare them, not to write them from memory.

00

Linear Search: Check Every Item

Linear search (also called sequential search) starts at the first item and checks one at a time until it finds the target or runs out of items. It works on any list, sorted or not.

def find(items, target): for item in items: if item == target: return True return False print(find([4, 8, 15, 16, 23, 42], 16)) # True

Click through a linear search for 16

Check 4. Not 16. Move on.

Check 8. Not 16.

Check 15. Not 16.

Check 16. Found it! The function returns True and stops. It took 4 checks.

return False is after the loop, not inside it. If it were inside, the function would give up after checking only the first item. This is a very common mistake.
01

Binary Search: Cut It in Half

Binary search looks at the middle item. If the target is smaller, it throws away the right half. If bigger, it throws away the left half. It repeats on what is left. It is much faster, but the list must be sorted.

Click through a binary search for 25

Look at the middle: 19. We want 25, which is bigger, so everything on the left (3, 8, 12, 19) is thrown away.

The middle of what is left is 31. We want 25, which is smaller, so throw away the right (31, 40).

Only 25 is left, and it is the target. Found it in 3 checks, and linear search would have needed 5.

Is the Algorithm Efficient?

An algorithm is efficient if it takes a reasonable amount of time as the input gets bigger. The exam compares two ways of growing.

GrowthExampleTimeCalled
steps grow like n, n squared, n cubed (a polynomial)loop through a list, nested loopsgrows slowly enough to finishreasonable time
steps grow like 2 to the n or n factorialtrying every combination of itemsdoubles with each new item, so it quickly takes longer than anyone can waitunreasonable time
  • For a problem with an unreasonable best-known algorithm, a heuristic can give a good-enough answer quickly, even if it is not the best one.
  • Some problems are undecidable: no algorithm can solve every case. The exam's example is the halting problem: no program can always tell whether another program will finish.
  • You do not compute exact step counts. You compare two algorithms and say which grows faster.
Exam habit: two loops one after the other is still reasonable. A loop inside a loop is bigger but still reasonable. Trying every possible arrangement is the sign of an unreasonable algorithm.

Practice Questions

Answer in your head, then check.

QuestionAnswer
A list of 10,000 names is not sorted. Which search can you use?Linear search only. Binary search needs a sorted list.
A sorted list has 1,000 items. About how many checks might binary search need?Around 10, because it halves the list each time (1,000 to 500 to 250 and so on).
An algorithm tries every possible route between 30 cities. Is it reasonable?No. The routes grow factorially, which is unreasonable time. A heuristic can find a good route.
True or false: a faster algorithm always gives a better answer.False. Binary search is faster, but only works on sorted data. Speed and requirements both matter.

Linear checks everything. Binary halves it. Both are reasonable.

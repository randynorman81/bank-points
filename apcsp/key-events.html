PYTHON NOTES  /  SUBJECT: RESPONDING TO THE KEYBOARD

Key Events

The keyboard's version of Mouse Events — same idea, one function that runs automatically, but the handler gets a slightly different kind of package back.

00

Definition

A key event lets your program run a function every time the user presses a key. You write a handler and register it with add_key_down_handler() — the same registration pattern as add_mouse_click_handler() from Mouse Events.

# General format def callback(event): key = event.key # do something based on which key it was add_key_down_handler(callback)

One parameter instead of two — and it's a bundle

Mouse click handlers get two separate parameters, x and y, handed straight to the function. Key handlers get just one parameter — conventionally called event — and that single object contains the useful information, accessed with a dot: event.key.

Mouse: info arrives split apart

def on_click(x, y): print(x, y)

Keyboard: info arrives bundled

def on_key(event): print(event.key)

event is just an object, exactly like the circle object from Graphics — it has attributes you access with a dot. event.key is a string: a single letter like "a" for a letter key, or a name like "ArrowLeft", "ArrowRight", "ArrowUp", or "ArrowDown" for the arrow keys.

Just like add_mouse_click_handler(callback), notice there are no parentheses after callback when it's registered. You're handing over the function itself so the canvas can call it later, on its own, every time a key goes down.
01

Examples

The canvas still has to exist first, exactly like every other Graphics page.

set_size(400, 300) square = Rectangle(40, 40) square.set_position(100, 100) add(square) def move_square(event): if event.key == "ArrowLeft": square.move(-15, 0) elif event.key == "ArrowRight": square.move(15, 0) elif event.key == "ArrowUp": square.move(0, -15) elif event.key == "ArrowDown": square.move(0, 15) add_key_down_handler(move_square)

An elif chain from the last two pages fits perfectly here — exactly one arrow key was pressed each time move_square runs, so only one branch should move the square.

Key release: add_key_up_handler()

The mirror image of add_key_down_handler() — runs when a key is released instead of pressed. Same handler shape, same event.key.

is_moving = False def start_moving(event): global is_moving is_moving = True def stop_moving(event): global is_moving is_moving = False add_key_down_handler(start_moving) add_key_up_handler(stop_moving)
This is the standard pattern for a game character that moves smoothly while a key is held, rather than jumping once per press — is_moving stays True for the entire time the key is down.
02

Common Problems / Errors

Forgetting the handler still needs a parameter: even if you never use it, the canvas always passes an event object to a key handler. A handler defined with no parameters crashes the instant a key is pressed.
def on_key(): # missing the event parameter print("key pressed") add_key_down_handler(on_key) TypeError: on_key() takes 0 positional arguments but 1 was given

Comparing to the wrong thing

if event.key == "left": won't match — the actual string is "ArrowLeft", not "left". Key names are exact and case-sensitive.

Forgetting global

Same rule as Mouse Events: reassigning a variable declared outside the handler (like is_moving) needs global as the first line inside the function, or Python raises an UnboundLocalError.

03

Python Code vs. Pseudocode

Same answer as Mouse Events: this doesn't exist in the official pseudocode at all.

The multiple-choice exam's pseudocode has no concept of a live keyboard. Responding to "the user just pressed this specific key, right now" is a graphics-library-specific skill — real code for your Create Performance Task, not something that shows up as pseudocode on the exam.
04

Spotify Examples (5)

Five keyboard shortcuts from a real music app, all built on the same handler pattern.

01

Spacebar play/pause

def handle_key(event): global is_playing if event.key == " ": is_playing = not is_playing add_key_down_handler(handle_key)

The spacebar's key string is just a single space character.

02

Arrow keys for volume

def adjust_volume(event): global volume if event.key == "ArrowUp": volume = min(volume + 5, 100) elif event.key == "ArrowDown": volume = max(volume - 5, 0) add_key_down_handler(adjust_volume)

min()/max() keep the value inside a valid 0–100 range.

03

Letter-key shortcuts

def shortcut(event): if event.key == "n": play_next_song() elif event.key == "p": play_previous_song() add_key_down_handler(shortcut)

Same idea as a real app's keyboard shortcuts — n for next, p for previous.

04

Escape to close a menu

def close_on_escape(event): global menu_open if event.key == "Escape": menu_open = False add_key_down_handler(close_on_escape)

"Escape" is the key's name, just like "ArrowLeft".

05

Hold-to-fast-forward

def start_ff(event): global is_ff if event.key == "ArrowRight": is_ff = True def stop_ff(event): global is_ff is_ff = False add_key_down_handler(start_ff) add_key_up_handler(stop_ff)

Fast-forwarding only while the key is physically held down.

One handler function, registered once, runs on every key press.The only real difference from a mouse handler is the shape of what gets passed in — a bundled event object instead of two loose numbers.

event.key tells you which key. elif tells your code what to do about it.

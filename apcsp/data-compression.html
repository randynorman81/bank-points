Data Compression

Raw data is big. A song, a photo, or a video can take up a huge amount of room, and big files are slow to send. Compression makes data smaller so it takes less storage and less time to send.

00

Why Compress?

Smaller data is cheaper to store and faster to send. There are two families of compression, and the difference matters a lot.

LosslessLossy (next lesson)
Original recoverable?Yes, exactlyNo, some data is gone for good
How small?somewhat smallermuch smaller
Used fortext, code, documents, ZIP, PNGphotos, music, video (JPEG, MP3)
Compression ratioCompressed size / original size. A 1,000-byte file that becomes 400 bytes has a ratio of 0.4, so it is 40% of the original. Smaller is better.
01

Idea 1: Run-Length Encoding

If the same thing repeats in a row, write it once and say how many times.

Try it: run-length encoding

Type text. Each run of the same character becomes a count and a character.

Run-length encoding shines on data with long runs, like a cartoon with big flat areas of one color. On data with no repeats, like ABC, it makes the file bigger (1A1B1C).
02

Idea 2: Repeated Patterns

Another trick: when a pattern appears many times, give it a short label and store the pattern once.

text = "the cat the cat the cat the dog" # label the pattern: 1 = "the cat " # compressed: 1 1 1 the dog # the table is kept once: 1 -> "the cat "

The compressed version needs the table too, so it only saves space when the pattern repeats often enough. This is the idea behind ZIP files.

No compression works on everything. Data that is already random or already compressed has no patterns left to remove, so trying to compress it again saves little or nothing.
03

Python: Compress and Decompress

Here is run-length encoding as code. Read it slowly: it uses the traversal pattern and a counter.

def compress(text): result = "" count = 1 for i in range(1, len(text)): if text[i] == text[i - 1]: count = count + 1 else: result = result + str(count) + text[i - 1] count = 1 result = result + str(count) + text[len(text) - 1] return result print(compress("AAAABBBCCD")) # 4A3B2C1D

Walk through AAB: i = 1 matches the letter before it, so count becomes 2. At i = 2 the letter changes, so we add 2A to the result and reset count to 1. After the loop we add the last run, 1B. The answer is 2A1B.

def decompress(code): result = "" count = "" for ch in code: if ch.isdigit(): count = count + ch else: result = result + ch * int(count) count = "" return result print(decompress("4A3B2C1D")) # AAAABBBCCD
If decompress(compress(x)) gives back x every time, the compression is lossless. That is the test.
04

On the AP Exam

Compression questions are about choosing and comparing, not about code.

  • Compression reduces the number of bits needed to store or send data.
  • Lossless compression lets you rebuild the exact original. Lossy does not.
  • Some data compresses well (lots of repeats) and some does not.
  • There is a trade-off: a smaller file can mean more work to compress and decompress, or lost detail.

Smaller, with nothing lost.

What if a little loss is okay? Then files can get much smaller. That is lossy compression.

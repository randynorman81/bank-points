Practice PT 3: Study Tracker

A program that collects five days of study time into a list, then reports the total, the best day, the average, and whether the goal was met. This page shows the finished program, a video plan, the reference sheet, and sample written responses.

00

What We Are Building

This project builds its list from the user's input and then passes the list into the procedure. That is one of the most common and strongest patterns for a Create Task.

Plan partThis program
Purposetrack a week of study time and tell the student if they met their goal
Inputthe minutes studied on each of five days
Outputthe total, the best day, the average, and a goal met or not met message
Functionalitystores the minutes in a list, loops to find the total and best day, and checks the goal
Why this is a strong project: the list is filled by input, passed as a parameter, and read by a loop. The goal parameter changes the message. Two different if statements each change the result.

The Personalized Project Reference

Four segments from your program, with every comment removed. This is exactly what each one looks like.

Procedure (i): the procedure

def weekly_report(daily, goal): total = 0 best = daily[0] for m in daily: total = total + m if m > best: best = m average = total / len(daily) print("Total minutes:", total) print("Best day:", best) print("Average:", average) if total >= goal: print("Goal met!") else: print("Goal not met. Short by", goal - total) return total

Procedure (ii): the call

result = weekly_report(minutes, 150)

List (i): where the data is stored

minutes = [] for day in range(1, 6): minutes.append(int(input("Minutes studied on day " + str(day) + "? ")))

List (ii): where the list is used

for m in daily: total = total + m if m > best: best = m
No comments and no course content. Check every segment for a # before you take the screenshots.

Sample Written Responses

Both the 2026 and the 2025 wording of each prompt, answered about this program. Yours will be about your program, so use these as a model for the shape of a good answer, never to copy.

Written Response 1 (2026): documentation

I would put a comment above weekly_report saying it goes through the list of daily minutes to find the total and the best day, then compares the total to the goal. Another programmer could read it to understand what the loop and the if statements are for.

Why it earns the point: It describes a real comment for a real segment and says how another programmer would use it.

Written Response 1 (2025): output

One output is the line Best day: 60. It shows the functionality because it reports the largest number in the list the user typed.

Why it earns the point: It names one real output and ties it to what the program does.

Written Response 2(a) (2026): the loop

The loop stops after the variable m has taken every value in the daily list, so after the fifth item, because a for loop over a list ends when it runs out of items.

Why it earns the point: It names the variable and the point where it stops, and says why.

Written Response 2(a) (2025): the Boolean expression

The Boolean expression is m > best. It is true when m is 60 and best is 45, because 60 is greater than 45, so best is updated.

Why it earns the point: It names the expression, a specific value that makes it true, and why.

Written Response 2(b) (2026): a call that behaves incorrectly

If I call weekly_report([0, 0, 0, 0, 0], 0), the procedure says Goal met! even though nothing was studied, because the total of 0 is greater than or equal to the goal of 0.

Why it earns the point: It gives real arguments, the wrong behavior, and why. The program still runs, so it is a logic error.

Written Response 2(b) (2025): a change that causes an error

A programmer could change > to < in the if m > best line. Then best would hold the smallest day instead of the largest, and Best day would be wrong.

Why it earns the point: It names a specific change and what the procedure does after it.

Written Response 2(c) (2026): managing complexity

The minutes list manages complexity because one variable holds all five days and one loop can add them. Without the list I would need five separate variables and repeated code to add them and find the best.

Why it earns the point: It says what the list lets the program do and what the code would need without it.

Written Response 2(c) (2025): adding new items

If a sixth day were added to the end of the list, the procedure would not need to change, because for m in daily and len(daily) use however many items are in the list. Only the range(1, 6) in the input loop would change.

Why it earns the point: It points to the exact code that needs no change, and honestly names the one line that does.

If, Elif, Else

Checking one thing gets you an if statement. Checking several things, in order, and picking exactly one outcome — that's what elif and else are for.

00

Definition

An elif ("else if") chain checks conditions in order, top to bottom, and runs the block under the first one that's true — then skips everything else in the chain, even if a later condition would also have been true. An else at the end catches whatever didn't match any condition above it, no condition needed.

grade = 85 if grade >= 90: print("A") elif grade >= 80: print("B") elif grade >= 70: print("C") else: print("Needs improvement")

With grade = 85: Python checks grade >= 90 first — false, skip it. Then grade >= 80 — true, so "B" prints, and Python stops right there. It never even looks at the >= 70 check or the else, even though 85 would technically satisfy >= 70 too.

Order matters — a lot

Because Python stops at the first match, checks that could overlap need to go from most specific to least specific — here, highest grade range first. Flip the order and the logic breaks:

Wrong order

if grade >= 70: print("C") elif grade >= 80: print("B") elif grade >= 90: print("A")

A 95 prints "C" — the very first check (>= 70) already matches, so the more specific >= 90 check never runs.

Correct order

if grade >= 90: print("A") elif grade >= 80: print("B") elif grade >= 70: print("C")

A 95 correctly prints "A" — the tightest, highest condition is checked first.

01

Examples

The key thing an elif chain guarantees: exactly one branch runs, never more than one.

elif chain — only one runs

x = 5 if x > 0: print("positive") elif x > -10: print("small negative")

Prints only "positive". Once the first condition matched, the chain stops.

separate ifs — both can run

x = 5 if x > 0: print("positive") if x > -10: print("small negative")

Prints both lines — two separate ifs each get checked independently, with no connection to each other at all.

This is the single biggest difference between an elif chain and a stack of separate if statements. Use elif when the branches represent mutually exclusive categories (a letter grade can only be one letter); use separate ifs when more than one thing might independently need to happen.

An if/elif chain doesn't need an else

else is optional. Without one, if none of the conditions match, the whole chain just does nothing — same as a plain if with no match.

day = "Sunday" if day == "Saturday": print("Weekend!") elif day == "Sunday": print("Weekend!") # no else -- any other day just prints nothing
02

Common Problems / Errors

Using separate ifs by accident: the most common bug on this page. If you meant "check these conditions in order, run only one branch" but wrote a stack of plain ifs instead of if/elif, more than one block can run when you only expected one.

else with a condition

else grade >= 60: SyntaxError: invalid syntax

else never takes a condition — it's the catch-all. A condition after it belongs on an elif instead.

Two words, not one

else if grade >= 60: SyntaxError: invalid syntax

Python's keyword is one word: elif. Writing it as two words (common if you've seen JavaScript's else if) doesn't work.

An elif or else has to line up at the same indentation as the if it belongs to, and can't have anything else between them. An extra blank line is fine; an extra statement at that indentation breaks the chain into two separate, unrelated conditionals.
03

Python Code vs. Pseudocode

Pseudocode nests its "otherwise" checks; Python flattens them into one chain.

ConceptAP CSP PseudocodePython
First checkIF (condition)if condition:
Next check, only if the first failedELSE IF (condition)elif condition:
Catch-all, no conditionELSEelse:
Pseudocode writes ELSE IF as two separate capitalized words; Python squashes it into the single keyword elif. Functionally, they mean exactly the same thing: check this next, only because everything above it already failed.
04

Spotify Examples (5)

Five real multi-branch decisions, each with exactly one outcome.

3-way chain

Subscription tier badge

if tier == "family": show_badge("Family") elif tier == "premium": show_badge("Premium") else: show_badge("Free")

Every account lands in exactly one tier.

ranges, ordered

Volume icon

if volume == 0: icon = "muted" elif volume < 50: icon = "low" else: icon = "high"

Checked most-specific (== 0) first, then the rest.

no else

Special-day themes

if is_holiday: apply_theme("festive") elif is_birthday: apply_theme("confetti") # any other day: default theme, nothing to do

Perfectly fine to leave off else when "do nothing" is the correct default.

combined condition

Audio quality

if is_premium and on_wifi: quality = "lossless" elif is_premium: quality = "high" else: quality = "standard"

Each branch's condition builds on the ones already ruled out above it.

why not separate ifs

Skip-limit warning levels

if skip_count >= 10: lock_skipping() elif skip_count >= 6: show_warning()

With separate ifs, hitting 10 skips would trigger both messages. elif guarantees only the more serious one fires.

elif chains pick exactly one branch. Separate ifs can run any number of them.Reach for elif whenever the outcomes are mutually exclusive categories — a grade, a tier, a warning level. That's almost always what "otherwise, check this" actually means.

Order top to bottom, first match wins, else catches the rest.

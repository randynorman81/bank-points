Video, Reference Sheet, Written Responses

Your code is only part of the Create Task. This page is the how-to for the video, the Personalized Project Reference, and the four written responses you write on exam day.

00

Making the Video

The video proves your program really runs. It must show input, at least one piece of functionality, and output. Plan it before you record it.

The rules

  • One minute or less and 30 MB or less.
  • File type: .mp4, .webm, .wmv, .avi, or .mov.
  • It must show the program running. A video of only code, screenshots, or a storyboard earns no credit.
  • No voice narration. Use text captions (words typed on the screen) if you want to explain something.
  • Nothing that identifies you. Use a made-up name when the program asks for one.
  • You make the video alone. No partner.

How to record it

DeviceWay to record the screen
ChromebookPress Shift + Ctrl + Show windows (or open Screen capture in the quick settings), choose Screen record.
WindowsPress Windows + G to open the Game Bar and record, or use the Snipping Tool's record option.
MacPress Shift + Command + 5 and choose Record selected portion.

Ask your teacher which tool your school allows. After recording, check the length and file size, and play it back to make sure the input, the functionality, and the output can all be seen clearly.

What to show, step by step

  • Start with the program ready to run and the output area visible.
  • Run it. Type the input slowly so a viewer can read it (for example the name, then each answer).
  • Make the program show different results: give one right answer and one wrong answer, so the viewer sees the selection and the loop working.
  • Let the final output stay on the screen for a couple of seconds.
  • Stop recording. Trim any extra time so the video is under 60 seconds.
01

Making the Personalized Project Reference

The PPR is four code segments pasted from your program. On exam day, you can use it while you write your answers, so choose segments that make the prompts easy to answer.

SegmentWhat it must show
Procedure (i)Your student-developed procedure. It has a name, one or more parameters that affect what it does, and an algorithm with sequencing, selection, and iteration.
Procedure (ii)A place in your program where that procedure is called.
List (i)Where the list is created and filled, so the data is stored in it.
List (ii)Where the same list is used: new data made from list items, or several items accessed, such as a loop through the list.
Remove every comment and any course content from the code before you take the screenshots. A comment or course content in your PPR means a score of 0 on the whole Create task, including your written responses. Screenshots must be sharp and the text at least 10 point.
Choose with the prompts in mind. The first loop in your Procedure (i) is the one 2(a) asks about. Your list segment (ii) is the one 2(c) asks about. Make sure each of those is code you can explain clearly in a couple of sentences.
02

The Four Written Prompts

On exam day you get 60 minutes and your PPR. You answer one question with one part and one question with three parts. The topics stay the same every year, but the exact wording changes.

PromptThe topic2025 wording (short)2026 wording (short)
WR 1Program design, function, and purposeIdentify one output your program produces and how it shows part of its functionality.Describe documentation that fits your program, and how another programmer could use it to understand a code segment.
WR 2(a)Algorithm developmentIdentify the Boolean expression in your first selection statement, a specific value that makes it true, and why.Identify the variables and values that make your first iteration statement stop, and why.
WR 2(b)Errors and testingDescribe a change another programmer could make to your procedure that causes a logic error, and what then happens.Give a call to your procedure with specific arguments that makes it behave incorrectly, describe it, and explain why.
WR 2(c)Data and procedural abstractionExplain how your list code would need to change if several new elements were added to the end of the list, or why it needs no change.Explain how your list manages complexity, and how your list code would change without the list.
These are short summaries, not the exact exam text. Because the wording changes, practice all of the versions on your own program. The Practice PTs in this unit give you sentence starters and sample answers for each one.
03

Writing Answers That Earn the Point

Scorers judge your answer only on what you write, and only against your own code. These habits come straight from the College Board's reports on what worked and what did not.

PromptDo thisNot this
WR 1Name one real output that the video shows, and explain how it shows the program's purpose.Do not describe the whole program, or an output the program never shows.
WR 2(a)Name the actual variables and the specific values that stop the loop, and say why those values stop it.Do not give a general set of values. Do not name the whole if or for line when asked for the condition.
WR 2(b)Give a specific call (real argument values), say what wrong thing happens, and say why it happens because of those values. Keep it a logic error: the program still runs, but gives a wrong result.Do not describe a syntax error. A program that will not run shows no behavior to evaluate.
WR 2(c)Say what the list lets the program do (for example, handle any number of items with one loop), and what the code would need without it (a separate variable and copy of the code for every item).Do not say only that the list is 'easier'. Be specific about the code.

Sentence starters

  • WR 1: "One output of my program is ___. It shows an aspect of the program's functionality because ___." (or) "I would add a comment above ___ that says ___. Another programmer could use it to understand ___."
  • WR 2(a): "The loop stops when the variable ___ reaches ___, because ___."
  • WR 2(b): "If I call ___(___, ___), the procedure would ___ instead of ___, because the value ___ makes ___."
  • WR 2(c): "The list ___ manages complexity because ___. Without the list, I would have to ___."
04

Final Checklist

Before you submit anything as final, check every box. After you submit, you cannot change it.

  • The program has input, a list with several items that is really used, a student-developed procedure with a parameter that matters, sequencing, selection, and iteration inside that procedure, a matching call, and output.
  • The program code PDF has comments that explain it and credit any code or help that is not yours.
  • The video is 60 seconds or less, 30 MB or less, one of the allowed file types, shows input, functionality, and output, and has no voice and no personal information.
  • The PPR has all four segments, no comments, and is sharp with text of 10 point or larger.
  • I made the video and the PPR alone.
  • I practiced all versions of the four written prompts on my own program.

A good plan, a clean reference sheet, and practice are what turn the program into points.

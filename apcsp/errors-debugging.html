02
A Debugging Routine
Do not change code at random. Follow a routine.
  1. Reproduce the problem. Find an input that fails every time.
  2. Read the error message, if there is one.
  3. Locate it: print values, or trace by hand, until you find the first place the value is wrong.
  4. Fix one thing, then test again with the failing input and the inputs that used to work.
  5. Keep a test that would have caught it, so it cannot come back.

AP
On the AP Exam
These are the ideas the exam asks about. Be ready to explain each one in your own words.
  • Know the four errors: syntax (breaks language rules, will not run), logic (runs, wrong result), run-time (crashes while running), overflow (number too big for its bits).
  • Debug with test cases, hand tracing, extra output, debuggers, and other people.
  • Test the edges: empty input, one item, zero, negative, and the biggest and smallest allowed values.
  • A logic error gives no message, so you must compare with the answer you expected.

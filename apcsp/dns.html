The Internet's Phone Book

Nobody types 142.250.80.46 to search the web. You type google.com. Something has to turn that name into the number. That is DNS, the Domain Name System.

Phone book: you look up a name and get a number. DNS translates a domain name (google.com) into an IP address (142.250.80.46).

Why bother? Names are easy to remember, and a site can change its IP address without anyone noticing, because DNS just updates the number next to the name.

02

The DNS Hierarchy

There is no single phone book for the whole Internet. It would be too big, and one failure would break everything. Instead DNS is a hierarchy spread over thousands of servers. It is a distributed system.

LevelIt knowsExample
1. Root serverswhich server handles each TLD"For .edu, ask that server."
2. TLD serverswhich server handles each domain"For schs.edu, ask that one."
3. The domain's name serverthe real IP address"schs.edu is 10.20.30.40."

Click through: looking up www.schs.edu

You type www.schs.edu. Your device asks its resolver (usually your ISP's or school's) for the IP address.
The resolver asks a root server. The root does not know the answer, but it knows who handles .edu.
The resolver asks the .edu (TLD) server. It does not know the IP either, but it knows which server handles schs.edu.
The resolver asks schs.edu's own name server. This one knows the real address: 10.20.30.40.
The resolver gives the address back to your device and remembers it (a cache) for next time.
03

Caching

Climbing the whole tree for every web page would be slow. So the resolver remembers answers in a cache. The next time anyone asks for schs.edu, the answer comes back instantly.

Try it: why a resolver keeps a cache

Look up the same site twice. The first time the resolver climbs the whole tree. The second time it answers from its memory.

A cache is a saved copy you check before doing the slow work. In Python it is a dictionary you look in first. You build one in the DNS walkthrough.
04

DNS and Security

Every site visit starts with a DNS answer, so DNS is a target. In DNS spoofing (also called cache poisoning) an attacker sneaks a fake answer into a cache, so yourbank.com quietly points to the attacker's server and you land on a look-alike site.

Defenses

HTTPS and its certificates (a fake site cannot prove it is the real one), DNSSEC (signed answers), and noticing warnings in your browser.

If DNS is down

Names stop working, but typing the IP address directly still would. The roads are fine. The phone book is missing.

AP

On the AP Exam

These are the ideas the exam asks about. Be ready to explain each one in your own words.

  • DNS translates domain names into IP addresses.
  • DNS is a hierarchy (root, TLD, domain name server) spread over many servers, so it scales and is fault tolerant.
  • A cache stores answers so the next lookup is faster. A TTL says how long an answer may be kept.
  • DNS spoofing gives a fake address. HTTPS certificates help you notice.

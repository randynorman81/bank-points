PYTHON NOTES  /  SUBJECT: COMBINING CONDITIONS

Logical Operators

and, or, and not — three words that combine or flip the booleans from the last page so an if statement can ask more than one question at a time.

00

Definition

A logical operator takes one or two booleans and produces a new boolean. Python has three: and, or, and not. Each one is a lowercase English word — not a symbol.

OperatorTrue when…ExampleResult
andboth sides are TrueTrue and FalseFalse
orat least one side is TrueTrue or FalseTrue
notflips a single booleannot TrueFalse
age = 15 is_teenager = age >= 13 and age <= 19 print(is_teenager) # True -- both comparisons have to be True is_weekend = False is_holiday = True day_off = is_weekend or is_holiday print(day_off) # True -- only one of the two needs to be True

Each side must already be a full boolean expression

A common instinct is to write age >= 13 and <= 19, the way you might say it out loud. Python doesn't allow that — every side of and/or needs its own complete comparison, variable and all.

Doesn't work

age >= 13 and <= 19 SyntaxError: invalid syntax

Repeat the variable

age >= 13 and age <= 19

Short-circuit evaluation

Python is lazy on purpose: in a and b, if a is already False, the whole expression has to be False no matter what b is — so Python never even checks b. Same idea for a or b: if a is already True, b never gets evaluated.

This isn't just a speed trick — it's why code like count > 0 and total / count > 5 is safe. If count is 0, the left side is False, Python short-circuits, and the division by zero on the right never actually runs.
01

Examples

These combine directly with the if statements and booleans from the last two pages — nothing new needed except the operator itself.

and, inline

A range check

if score >= 90 and score <= 100: print("A")

Both comparisons must hold for the body to run.

or, inline

Multiple valid answers

if answer == "y" or answer == "yes": print("Confirmed")

Either spelling is accepted.

not, on a stored boolean

Checking the opposite

if not is_muted: play_sound()

Runs whenever is_muted is False.

combining all three

Stacking conditions

if is_logged_in and (is_admin or is_owner): print("Access granted")

Parentheses group the or so it's checked as one unit first.

02

Common Problems / Errors

& / | vs and / or: & and | are bitwise operators for working on the individual bits of numbers — they are not the same as and/or and can produce confusing results if swapped in by accident. For combining booleans, always use the English words.

"or" doesn't mean exclusive-or

In everyday English, "coffee or tea" often implies picking exactly one. Python's or is inclusive — True or True is still just True. If both sides are true, or is still true.

Operator precedence

not binds tighter than and, which binds tighter than or. not a or b means (not a) or b — not not (a or b). When in doubt, add parentheses to say exactly what you mean.

is_admin = False is_banned = True # Meant to check: "not (admin or banned)" -- neither special case applies can_edit = not is_admin or is_banned print(can_edit) # True -- NOT what was probably intended! # What was actually meant: can_edit_fixed = not (is_admin or is_banned) print(can_edit_fixed) # False
Whenever not is supposed to apply to more than just the very next thing, wrap that part in parentheses. It costs nothing and removes all doubt.
03

Python Code vs. Pseudocode

Same three ideas, different capitalization.

ConceptAP CSP PseudocodePython
Both must be trueANDand
At least one must be trueORor
Flip a booleanNOTnot
The AP Reference Sheet always writes these in ALL CAPS — AND, OR, NOT — as part of a larger conditional statement, e.g. IF(condition1 AND condition2). Python lowercases all three and drops the parentheses requirement around the whole condition, but the logic itself doesn't change at all.

Spotify Examples (5)

Five real access-and-behavior rules from a music app, each one a combination of booleans.

and

Show the waveform animation

if is_playing and not is_muted: show_waveform()

Only animate when there's actually sound to show.

or

Custom queue behavior

if is_shuffle_on or is_radio_mode: build_dynamic_queue()

Either feature on its own changes how the next song gets picked.

or, with a comparison

Playback access

if is_premium or trial_days_left > 0: allow_playback()

A paid account or an active trial — either one unlocks playback.

not, wrapping and

Blocking explicit content

if not (is_explicit and parental_controls_on): play_song()

Only skip the song when both conditions are true at once — explicit and controls on.

and, short-circuit safe

Free-tier skip limit

if skip_count >= 6 and time_elapsed < 3600: show_upgrade_prompt()

Both must hold: six-plus skips within the hour, not ever.

Three words. That's all it takes to combine any number of booleans into one condition.

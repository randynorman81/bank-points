8.3 — User Input

🔔 Bell Ringer — Think About It
  1. input() pauses a Python program and waits for the person running it to type something. Why is a program that can react to what a person types more useful than one that always does the exact same thing?
  2. Everything input() receives comes back as a string, even if the person typed a number. Why might that cause a bug if you try to do math with it right away?
  3. int() converts a string to a whole number. Why does Python make you convert it explicitly instead of just guessing what you meant?
  4. Describe a program you'd want to build that needs to ask the user a question and use their answer.

Notes

Look up these definitions:

  • input()
  • Type conversion (int(), float(), str())

Key idea: input() pauses your program, displays a prompt, and waits for the person using it to type a response — but whatever they type always comes back as a string, even if it looks like a number. To use that input in math, you have to explicitly convert it with int() or float(), or Python will either error out or treat it as text instead of a number. This is the same user-input idea you'll recognize from Arduino's Serial input, just running on a computer instead of a physical board.

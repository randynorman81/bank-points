9.5 — Floating Point Numbers and Rounding

🔔 Bell Ringer — Think About It
  1. Comparing two floating point numbers with == can behave strangely (0.1 + 0.2 == 0.3 is actually False in most languages). Why do you think tiny rounding errors happen inside a computer's math?
  2. round(x) rounds to the nearest whole number, and round(x, n) rounds to n decimal places. When would you want to round money to 2 decimal places instead of 0?
  3. Why might it be safer to compare rounded values instead of comparing raw floating point numbers directly?
  4. Where in a program you might build (a game score, a price calculator) would floating point rounding actually matter?

Notes

Look up these definitions:

  • Floating point number
  • round()
  • Rounding error

Key idea: Computers store decimal numbers in a format that can't always represent them with perfect precision, which is why comparing floating point numbers directly with == can behave unexpectedly — two numbers that should be mathematically equal might differ by a tiny fraction. round(x) rounds to the nearest whole number, and round(x, n) rounds to n decimal places, which is the standard fix: round values before comparing them, or before displaying them to a user (like rounding a price to 2 decimal places). This is a subtle but real issue that shows up in any program doing decimal math.

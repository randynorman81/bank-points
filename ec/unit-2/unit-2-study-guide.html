2.1 — Meet the Arduino (Analog vs. Digital)

Analog
A continuous signal that changes smoothly, with no steps — it copies the real-world thing directly. Examples from the assignment: a mercury thermometer, a vinyl record or cassette tape, a VHS tape.
Digital
Information stored as discrete steps / numbers (ultimately 1s and 0s) and processed by electronics and software. Examples: a digital weather app, a CD or streaming app, a Blu-ray or Netflix.
analogRead()
Reads the voltage on an analog input pin (A0–A5) and converts it into a whole number from 0 to 1023. Used for sensors that give a range of values.
digitalRead()
Checks a digital pin and returns only HIGH (about 5V) or LOW (0V). Used for on/off inputs like a button or switch.
The board vs. the IDE
The Arduino IDE is software you write code in; the Arduino Uno is the hardware the code runs on. The Uno contains the ATmega328P microcontroller chip. Its digital pins 0–13 are HIGH or LOW only; its analog pins A0–A5 read a range.

2.2 — First Circuit and 2.2A — Dual-LED Lab

In 2.2 you wired an LED and a 220Ω resistor (bands Red-Red-Brown-Gold) straight to the Uno's 5V and GND. No code was involved, so that LED was simply always on. In 2.2A you powered two LEDs from the breadboard's power rails, then broke the circuit on purpose to see what fails.

Why simulate first
In Tinkercad, mistakes are free — no real component gets damaged and nobody gets hurt.
Breadboard rows and the center divider
The 5 holes a–e in one row are connected inside the board; so are the 5 holes f–j. The center divider keeps the two halves separate — that's why a part can straddle it, and why an LED placed "across the divide" (2.2) needs its own connections on the other side.
Power rails
The long rails on the sides run the length of the board: red (+) and black (−). One wire from 5V and one from GND let many parts share power.
Polarity: anode and cathode
An LED is a diode — current flows through it in only one direction. The anode (+) is the longer / bent leg and connects toward 5V; the cathode (−) is the shorter / straight leg and connects toward GND. Reverse the polarity and the LED does not light.
Both legs in the same row
Anode in a11 and cathode in b11 = both legs on the same connected row, the same electrical point. No current flows through the LED, so it won't light.
Parallel circuit
In 2.2A each LED had its own path (+ rail → resistor → LED → − rail). Separate branching paths = parallel. Unplug the Red LED and the Green LED stays lit, because its own path is still complete.
Experiment A: short-circuiting the LED
Moving the Green LED's ground wire from its cathode row (20) into its anode row (21) gives current an easier path straight to ground, so it bypasses the LED — the Green LED goes dark.
Experiment B: overcurrent failure
Replacing the Red LED's resistor with a plain wire: Tinkercad shows an explosion symbol and warns that the current is far over the LED's 20 mA maximum. The Green LED survives because it still has its own resistor. That's also why two LEDs shouldn't share one resistor — each branch needs its own.

2.3 — Blink Sketch

Why the wiring changed from 2.2: the LED now goes to a digital pin (pin 8) and GND. Set to OUTPUT and driven HIGH, the pin becomes its own tiny 5V source; driven LOW, it drops to 0V, just like GND. The pin does the powering, on a schedule your code controls.

int ledPin = 8; // above setup() and loop(): names the pin void setup() { pinMode(ledPin, OUTPUT); // runs ONCE: this pin sends power OUT } void loop() { // runs FOREVER, top to bottom digitalWrite(ledPin, HIGH); // 5V: LED ON delay(1000); // wait 1000 milliseconds = 1 second digitalWrite(ledPin, LOW); // 0V: LED OFF delay(1000); // wait again, then loop() repeats }
TermMeaning (from the 2.3 matching activity)
setup()Runs exactly once when the board first gets power — the place to set up pins.
loop()Runs over and over forever until power is disconnected.
pinMode()Sets a pin to behave as an INPUT or an OUTPUT.
digitalWrite(pin, HIGH)Sends 5V out of the pin.
digitalWrite(pin, LOW)Sets the pin to 0V (ground).
delay(ms)Pauses the program for a number of milliseconds.
intStores a whole number — used to name pin numbers at the top.
Timing math
1000 ms = 1 second, 500 ms = half a second, 250 ms = a quarter second, 2000 ms = 2 seconds. ON for a quarter second and OFF for 2 seconds: digitalWrite(ledPin, HIGH); delay(250); digitalWrite(ledPin, LOW); delay(2000);
pinMode() inside loop() by mistake
The LED still blinks — pinMode() just gets re-run every pass for no reason. It only ever needs to happen once, which is why it belongs in setup().
Forgetting the second delay()
The LED turns OFF and loop() instantly restarts and turns it back ON. It's off for only a tiny instant, so it looks like it's always on.
The flashing red signal (Part 2)
Each of the 3 LEDs gets its own digital pin (8, 9, 10) and its own resistor; they can share one GND. The three digitalWrite(..., HIGH) lines run one after another in the same pass, so close together that the LEDs look perfectly in sync. Flashing signals blink about once per second (roughly 500 ms on, 500 ms off).

Global variables
Declared at the very top, above setup(), so any function can use them. A variable declared inside loop() gets reset every time loop() restarts — a counter there would never climb.
Why use a variable like blinkSpeed
Change one number at the top and every delay(blinkSpeed) changes with it.
Byte wraparound (Part 2)
When blinkCount (a byte) is 255 and you add 1, it wraps around to 0. At that same moment, totalBlinks (a long) just keeps counting up, because a long can hold numbers over 2 billion.
Serial Monitor
Serial.begin(9600); goes inside setup() to start communication with the computer. Serial.print() prints on the same line; Serial.println() prints and then moves to a new line.
Choosing a type
Microcontrollers have very little memory, so use the smallest type that does the job: a boolean for on/off, a byte for 0–255, a float only when you need decimals.

2.5 — PWM: Controlling Brightness

PWM (Pulse Width Modulation)
The LED is still only ever fully on or fully off — there's no "in between" on a digital pin. PWM switches it on and off super fast, faster than your eyes can see. On most of the time = looks bright; on just a little = looks dim. The duty cycle is the percent of time it's on.
Moving from pin 8 to pin 9
Only pins with a ~ can do PWM: 3, 5, 6, 9, 10, 11. Pin 8 can't — which is why you moved your LED to pin 9 and changed int ledPin = 9;.
analogWrite(pin, value)
Like digitalWrite(), but instead of HIGH/LOW you give it 0 to 255: 0 = off, 128 ≈ half, 255 = full brightness.
analogWrite(ledPin, 50); delay(1000); // dim analogWrite(ledPin, 150); delay(1000); // medium analogWrite(ledPin, 255); delay(1000); // full brightness, then loop() repeats

2.6 — Timing and Sequences

Three LEDs — red (pin 8), yellow (pin 9), green (pin 10) — cycling like a traffic light.

Wiring
Each LED gets its own resistor and its own digital pin, but all 3 can share one GND, because GND is just a shared return path. No PWM pin needed — you're only turning lights fully on and off, not dimming.
int greenTime = 5000; int yellowTime = 1500; int redTime = 4000; void loop() { digitalWrite(greenPin, HIGH); delay(greenTime); digitalWrite(greenPin, LOW); digitalWrite(yellowPin, HIGH); delay(yellowTime); digitalWrite(yellowPin, LOW); digitalWrite(redPin, HIGH); delay(redTime); digitalWrite(redPin, LOW); } // green → yellow → red → back to green, forever
Sequence and timing
A sequence is digitalWrite() + delay() in a deliberate order. Real lights aren't equal: green is longest, yellow is shortest.
Delay variables: pros and cons
Pro: change a light's timing in one place, and the code explains itself (delay(yellowTime) vs. delay(1500)). Con: a few extra lines at the top. Without variables you'd type the numbers straight in: delay(5000), delay(1500), delay(4000).
Blocking code
delay() pauses the entire program — nothing else can happen while it counts down.
The Zombie Grid Hack
If digitalWrite(yellowPin, LOW); is deleted, yellow turns on and never turns off. By the second pass, yellow stays on the whole time while green and red still take their turns — so two lights are on at once. Re-inserting digitalWrite(yellowPin, LOW); fixes it.

2.7 — Circuit Fundamentals (Buttons and Pull-Ups)

Source vs. sink
A pin set HIGH pushes current out = sourcing. A pin set LOW that current flows into = sinking.
Floating pin
An input connected to nothing solid — not 5V, not GND. It randomly flickers between HIGH and LOW because it picks up electrical noise from the air. An unpressed button with nothing else connected is floating. (The Haunted Elevator: static from a fuzzy sweater "presses" the button.)
Pull-up resistor / INPUT_PULLUP
Connects the pin to 5V by default, so it reads a clean, steady HIGH when nothing is pressed; pressing the button connects it to GND for a clean LOW. The Arduino has one built in: pinMode(buttonPin, INPUT_PULLUP);. It "pulls" the pin to a known state so noise can't flip it.
Reads "backwards"
With INPUT_PULLUP: not pressed = HIGH, pressed = LOW. That's normal, not a bug. (The Backwards Doorbell: code that buzzes when buttonState == HIGH buzzes constantly when nobody touches it, and goes quiet the moment someone presses it.)
digitalRead() and the !
int buttonState = digitalRead(buttonPin); reads the button. digitalWrite(ledPin, !buttonState); flips it, so the LED is on while the button is pressed.
Red light / walking light
digitalWrite(redPin, buttonState); and digitalWrite(walkPin, !buttonState); are always opposites: red on by default, walk light on only while pressed — never both at once. It updates instantly because nothing is blocking loop() with a delay().
Wiring the 4-leg button
The 4 legs are really 2 pairs; pressing bridges the pairs. Straddle the button across the center gap, then one leg to your digital pin and one leg from the other side to GND.
Ohm's Law and the pin limit
V = I × R (voltage = current × resistance). The Uno's pins handle only about 40 mA, which is why every LED gets a resistor to limit current.

2.8 — Interpreted vs. Compiled (Podcast)

The French-book analogy
Interpreted = a friend reads a French book aloud, translating one sentence at a time, live. Python works this way: code is read and run line by line as it's needed. Compiled = translate the whole book first, cover to cover, then read straight through fast. Arduino's C++ works this way.
Why Arduino uses a compiled language
An Arduino has a tiny amount of memory and no operating system. Translating everything ahead of time makes the finished program small and fast, and it never wastes time or memory translating while it should be doing its real job.
What Upload really does
Step 1: compile — translate the whole sketch into machine code and check for mistakes. A typo or missing semicolon is caught here, before anything reaches the board. Step 2: upload the machine code over the USB cable. Almost every "my code won't work" moment this unit happened at step 1.

2.9 — Unit Build: 7+ Letter Word Morse Code Flasher

One LED flashes a real word, at least 7 letters long, in Morse code — slowly and clearly enough that a partner who doesn't know the word can decode it.

The Morse timing rules
Everything is built from one unit of time. A dot = 1 unit. A dash = 3 units — always exactly 3 times as long as a dot. The standard gaps (LED off): 1 unit between symbols inside a letter, 3 units between letters, and 7 units before the word repeats. The gap between letters must be noticeably longer than the gap inside a letter, or nobody could tell where one letter ends.
Timing variables
Make the unit a variable (for example int unit = 300;) and build every time from it: delay(unit) for a dot, delay(unit * 3) for a dash. Change one number to speed up or slow down the whole word.
Which pin?
Morse is only fully on or fully off, using digitalWrite() — so a regular digital pin works; no PWM pin is needed. The LED still needs its resistor (2.2, 2.7), and the pin still needs pinMode(pin, OUTPUT) in setup().
Requirements
A real 7+ letter word; accurate Morse for every letter (look it up, don't guess); symbol gaps clearly shorter than letter gaps; the word repeats in loop() forever; at least one timing variable with a comment; every line commented; a partner can decode it.
// Letter S = dot dot dot, O = dash dash dash digitalWrite(ledPin, HIGH); delay(unit); // dot (1 unit on) digitalWrite(ledPin, LOW); delay(unit); // gap inside the letter (1 unit off) digitalWrite(ledPin, HIGH); delay(unit * 3); // dash (3 units on) digitalWrite(ledPin, LOW); delay(unit * 3); // gap between letters (3 units off)

01

Source and Sink

Current has to come from somewhere and go somewhere. A pin can be either end of that trip.

Sourcing

A pin set HIGH pushes current out to whatever it's connected to. Every LED you've lit with digitalWrite(pin, HIGH) was powered by a pin sourcing current.

Sinking

A pin set LOW, with something else pushing current into it, is sinking current: soaking it up, like a drain.

02

Floating Pins and Pull-Up Resistors

Part 3, Question 8

An input pin that isn't connected to 5V or GND doesn't calmly sit at 0. It "floats," picking up tiny bits of electrical noise from the air, your hand, even a static-charged sweater nearby. It reads HIGH, then LOW, then HIGH, at random.

The pull-up resistor

Connects the pin to 5V by default, so with nothing happening it reads a clean, steady HIGH. Pressing the button connects the pin straight to GND, so it reads a clean LOW. It holds the pin in place the way gravity holds things down.

Built in: INPUT_PULLUP

The Arduino has a pull-up resistor inside it. Turn it on with pinMode(buttonPin, INPUT_PULLUP);. No separate resistor is needed for the button. Plain INPUT has no pull-up, so an unpressed button floats.

03

Wiring the Button: 4 Legs, 2 Connections

The button has 4 legs, but it isn't 4 separate connections. It's really 2 pairs. Pressing the button is what bridges the two pairs together. Hold the button below to see it.

The standard way: straddle the button across the breadboard's center gap so one pair lands on each side. Then take any one leg from one side to your digital pin, and any one leg from the other side to GND. Which exact leg doesn't matter, only which side.
04

Part 1: Button Turns On an LED

Part 1 + Question 1

With INPUT_PULLUP, the button reads backwards from what feels natural: HIGH when NOT pressed, LOW when pressed. That's normal, not a mistake. One exclamation point flips it back so pressing turns the light on.

int buttonPin = 8; int ledPin = 9; void setup() { pinMode(buttonPin, INPUT_PULLUP); // built-in pull-up: reads HIGH when not pressed pinMode(ledPin, OUTPUT); } void loop() { int buttonState = digitalRead(buttonPin); // NEW: read the pin, don't write it digitalWrite(ledPin, !buttonState); // flip it: pressed (LOW) becomes HIGH }

Hold the button (mouse or finger)

digitalRead(pin)

New command. Instead of writing a value out to a pin, it reads whatever is on the pin right now and gives back HIGH (1) or LOW (0). You store it in a variable: buttonState.

The doorbell analogy (Question 1)

Think through how a real doorbell works: what's waiting, what happens when the button is pushed, and what happens when it's let go. Then match each piece of the doorbell to a piece of your circuit and code: the button, the wire, the pin reading, and the LED.

05

Part 2: Red Light / Walking Light

Part 2

A crosswalk: red is on by default, and while someone holds the button, the walking light takes over. The trick is using the button reading two ways, once as-is and once flipped.

void loop() { int buttonState = digitalRead(buttonPin); digitalWrite(redPin, buttonState); // as-is: HIGH when not pressed digitalWrite(walkPin, !buttonState); // flipped: HIGH when pressed }
No delay() here. Nothing pauses loop(), so it reads the button thousands of times a second and the lights react instantly. Wire each LED with its own resistor and its own pin; the button and LEDs can all share one GND.

Ohm's Law: the Math Behind Every Resistor

Every LED you've wired had a resistor, and now you can see why the numbers work out. Voltage, current, and resistance are tied together by one equation.

V = I × R

V = voltage (volts), I = current (amps), R = resistance (ohms, Ω). Rearranged: I = V ÷ R and R = V ÷ I.

Why it matters

An LED is usually happy around 20 mA, and an Uno pin maxes out around 40 mA. Too little resistance means too much current, which can burn out the LED or damage the pin.

Test yourself

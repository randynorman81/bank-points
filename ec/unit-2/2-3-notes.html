01

Why the Wiring Changed from 2.2

Intro + Section 2

In 2.2 your LED glowed the second you hit Start Simulation, and it never stopped. It was plugged straight into the power. Today, the same LED does what your code tells it to, because it's plugged into a pin your code controls.

2.2: wired to 5V and GND

The LED is connected to the 5V pin and the GND pin. 5V is always on, so the LED is always on. No code is involved at all.

2.3: wired to a digital pin and GND

The LED is connected to a digital pin (like pin 8) and GND. The pin only sends power when your code says so.

The big idea: a digital pin set to OUTPUT with pinMode() can act like its own tiny power source. HIGH makes it 5V, exactly like the 5V pin. LOW makes it 0V, exactly like GND. Click the two buttons above to see it.

03

Building Blink, Line by Line

Section 3: Part 1

Tinkercad's code editor starts you with an empty setup() and an empty loop(). Every Arduino program needs both of them, no exceptions. Your job is to fill them in.

int ledPin = 8; // ABOVE setup(): name the pin you wired to void setup() { pinMode(ledPin, OUTPUT); // runs once: this pin sends power OUT } void loop() { digitalWrite(ledPin, HIGH); // LED on delay(1000); // wait 1 second digitalWrite(ledPin, LOW); // LED off delay(1000); // wait 1 second, then loop() starts over }
Where it goesLineWhy
Above setup() and loop()int ledPin = 8;Names your LED's pin. Use the pin number you actually wired to.
Inside setup()pinMode(ledPin, OUTPUT);The pin will send power out. Only needs to happen once.
loop(), 1st linedigitalWrite(ledPin, HIGH);Starts the "on" half of the blink.
loop(), 2nd linedelay(1000);Keeps the LED on long enough to see.
loop(), 3rd linedigitalWrite(ledPin, LOW);Starts the "off" half of the blink.
loop(), 4th linedelay(1000);Keeps it off before loop() repeats from the top.

Commenting every line (Step 5)

A comment starts with //. The Arduino ignores everything after it on that line, so you can explain your code in plain English. Say what the line does, like the gray comments above.

Making it your own (Step 4)

Change the two delay() numbers so they aren't 1000 and 1000. The first delay controls how long the LED is on; the second controls how long it's off. Different numbers make an uneven blink.

Submitting (Step 6): take a screenshot that shows your working circuit and your commented code, then paste it into your assignment doc.
04

Watch loop() Run

Section 4

The Arduino reads your code from top to bottom, one line at a time. setup() gets one trip. loop() gets a trip that never ends. Watch the highlight move, then experiment: change a delay, or turn a line off and see what the LED does.

stopped
loop() trips: 0

The simulator runs at real speed, so 1000 means 1 real second. Unchecking a line removes it from the code.

Once vs. forever

Anything inside setup() happens a single time. Anything inside loop() happens again on every trip, thousands of times a minute if nothing slows it down. Before you move a line between them, ask: does this need to happen once, or every time?

The bottom of loop() is not a stop sign

When loop() reaches its last line, it jumps straight back to the first line with no pause of its own. The only waiting that happens is the waiting you write with delay(). Try turning off each delay() in the simulator and watch what changes.

Thinking in Milliseconds

Section 4 + Section 5

delay() doesn't speak in seconds. It speaks in milliseconds: thousandths of a second. Once you can convert between the two, every timing question is just multiplication.

This picture follows the ON and OFF numbers in the calculator below. One full blink = ON time + OFF time.

Seconds → milliseconds

Multiply by 1000. Examples: 1 second = 1000 ms, half a second = 500 ms, 3 seconds = 3000 ms.

06

Extension: The Flashing Red Signal

Section 5: Part 2

At a railroad crossing, or at an intersection late at night, a traffic light sometimes just flashes red. It means "treat this like a stop sign." Every red light on that signal flashes together. You're building that with 3 LEDs.

The pattern: repeat for each LED

// top: one int per LED int led1Pin = 8; // then led2Pin, led3Pin // setup(): one pinMode per LED, all OUTPUT // loop(): // all 3 digitalWrite HIGH, back to back // ONE delay // all 3 digitalWrite LOW, back to back // ONE delay

Why they look perfectly in sync

The three HIGH lines run one right after another in the same trip through loop(). The Arduino finishes all three in a few millionths of a second, far too fast for your eyes to notice the difference. So the LEDs appear to turn on at exactly the same moment.

Why each LED gets its own pin: the assignment asks you to make them flash together with your code, not your wiring. When each LED has its own pin, your code can control every LED separately. That matters later: a real traffic light needs to turn one color on while another is off, and that's only possible if each light has its own pin.

Most first-time bugs in this lesson aren't about electronics at all. They're tiny slips that stop everything. Test yourself: click the answer you think fixes each one.

A pin that turns on and off on a schedule your code controls: that's all Blink is.

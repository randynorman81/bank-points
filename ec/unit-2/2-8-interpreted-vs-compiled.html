2.8 — Interpreted vs Compiled + How Arduino Code Works

🔔 Bell Ringer — Think About It
  1. Arduino's creators chose a compiled language even though interpreted languages like Python are often easier to write and debug. Why would "harder for humans" ever be an acceptable tradeoff for a computer that has almost no memory or power to spare?
  2. Clicking Upload actually does two separate jobs back to back — compiling, then uploading. Most of your bugs so far this unit happened at the compiling stage, not the uploading stage. Why do you think catching an error before the code ever reaches the board matters so much on a microcontroller?
  3. An interpreted language reads and runs your code line by line, in real time, every single time it runs. Why would that be riskier, or just slower, on a device controlling something safety-critical, like a car's airbag or a medical machine?
  4. If Arduino had chosen an interpreted language instead, what's one thing about this entire unit — Blink, PWM, the traffic light build — that you think would have worked differently, or worse?

Notes

Look up these definitions:

  • Interpreted language
  • Compiled language
  • Compiling

Key idea: an interpreted language (like Python) is read and run line by line by an interpreter, in real time. A compiled language (like C++, which Arduino uses) is fully translated into machine code all at once, before it ever runs — which is faster and more predictable on a microcontroller with limited memory and power. Clicking Upload does two separate steps back to back: first the IDE compiles your code (and catches syntax errors here), then it uploads the compiled machine code to the board over USB. Most of your early troubleshooting this unit was actually compiling errors, not uploading errors.

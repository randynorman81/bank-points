2.8 — Interpreted vs Compiled + How Arduino Code Works

No hardware today — a discussion and research day, plus your last non-build lesson before the unit build and test.

Intro

Ask AI these questions; look over the answers.

  1. What is the difference between an interpreted programming language and a compiled programming language? Give me one real example of each.
  2. Explain to a middle schooler what happens when you click "Upload" in the Arduino IDE — where does your code actually go?
  3. Create a simple flowchart showing the steps from writing C++ code in the Arduino IDE to that code actually running on the physical board.
  4. Why does Arduino use a compiled language (C++) instead of an interpreted language like Python? What's the advantage for a microcontroller specifically?
  5. Connect the idea of "translating something completely before using it" versus "translating it as you go" to a real-world example I might understand — like reading instructions or following a recipe.
  6. What real companies or industries care a lot about the difference between compiled and interpreted code, and why does it matter to them?

Notes

Look up these definitions:

  • Interpreted language
  • Compiled language
  • Compiling

Key idea: an interpreted language (like Python) is read and run line by line by an interpreter, in real time. A compiled language (like C++, which Arduino uses) is fully translated into machine code all at once, before it ever runs — which is faster and more predictable on a microcontroller with limited memory and power. Clicking Upload does two separate steps back to back: first the IDE compiles your code (and catches syntax errors here), then it uploads the compiled machine code to the board over USB. Most of your early troubleshooting this unit was actually compiling errors, not uploading errors.

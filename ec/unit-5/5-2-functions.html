5.2 — Functions

🔔 Bell Ringer — Think About It
  1. You already wrote custom functions in your Unit 3 Tinkercad code (like setColor() or showDigit()). What's one function you remember writing, and what job did it do?
  2. A function can take in a parameter and hand back a return value. Describe a real-life "function" — something that takes an input and produces an output.
  3. If you copy the same five lines of code into ten different spots in a program, what happens when you find a bug in those lines?
  4. Why might a programmer choose to break a big program into many small functions instead of writing one long list of instructions?

Notes

Look up these definitions:

  • Function
  • Parameter
  • Return value
  • Function signature

Key idea: A function is a named, reusable block of code — exactly like the setColor() or showDigit() functions you wrote in Unit 3, just in plain C++ instead of on an Arduino. A function can accept parameters (values handed in) and can return a value (a result handed back) using the return keyword. Breaking a program into small functions, each with one clear job, means a bug only needs to be fixed in one place instead of everywhere you copy-pasted the same code.

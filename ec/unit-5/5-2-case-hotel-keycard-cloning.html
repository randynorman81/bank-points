5.2 — Case: Hotel Keycard Cloning

The real-world version of yesterday's UID weakness — you're about to build this exact system as V1.

Intro

Ask AI these questions; look over the answers.

  1. How do hotel keycard cloning attacks actually work? What equipment is needed?
  2. Explain to a middle schooler how someone could copy a hotel keycard without ever touching it or the room it belongs to.
  3. Create a simple timeline showing how an attacker might clone a card and gain unauthorized room access, step by step.
  4. Why have hotels historically been slow to upgrade to more secure RFID systems, even knowing about this vulnerability?
  5. Connect this case directly to what you learned last lesson about UIDs — what specifically makes a hotel keycard clonable?
  6. What would a more secure hotel keycard system look like? What would it need beyond just a UID?

Notes

Look up these definitions:

  • RFID cloning
  • Encryption
  • Legacy system
  • Wireless interception

Background: RFID hotel keycards can be cloned using inexpensive readers that copy a card's UID, sometimes without touching the card or the cardholder ever knowing. A cloned card grants identical access, since basic systems only check whether a presented UID matches. Hotels have been slow to upgrade because replacing every door lock/card system across a property is expensive and disruptive — a legacy system persists when the cost of replacement outweighs the perceived risk. A real fix requires encryption — scrambling card data so a copy is useless without the key. Honest limitation to know now: this unit's V1 (next lesson) intentionally uses this exact weak approach, and even V2/V3 don't fully fix it — they add functionality, not security.

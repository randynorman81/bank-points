12.3 — Namespaces in Functions

🔔 Bell Ringer — Think About It
  1. A variable created inside a function only exists inside that function — it's local. Why might that be a safety feature rather than a limitation?
  2. A variable created outside any function is global and can be seen everywhere. Why might relying too heavily on global variables cause problems in a large program?
  3. If two different functions each create their own variable named count, do you think they'd interfere with each other? Why or why not?
  4. Why do you think professional programmers are generally taught to prefer local variables and parameters over global variables?

Notes

📄 Notes: Namespaces in Functions (everything you need for the lesson)

Look up these definitions:

  • Local variable
  • Global variable
  • Scope

Key idea: A variable's scope is where in the program it can be seen and used. A local variable, created inside a function, only exists while that function is running and is invisible everywhere else — which means two different functions can each safely use a variable named count without conflicting. A global variable, created outside any function, can be seen and changed from anywhere in the program, which is occasionally useful but can also make a program harder to reason about, since any function might be changing it.

12.2 — If/Else Statements (Buttons)

🔔 Bell Ringer — Think About It
  1. A button is a new kind of input you haven't used yet this year. What do you think digitalRead() returns when a button is pressed versus not pressed?
  2. You used if/else constantly across C++, Python, and Tracy this year. What do you think is different about using it here, with a real (simulated) button as the input?
  3. Why might a circuit need conditionals at all — what would happen if a button press just always did the same thing regardless of any condition?
  4. Predict one bug you might run into wiring and coding a button for the first time in a while.

Notes

Look up these definitions:

  • digitalRead() (review)
  • Button (pushbutton)
  • INPUT_PULLUP (review)

Key idea: This lesson uses buttons as a new input, read with digitalRead(), and conditionals to decide what the circuit does based on whether the button is pressed. This connects directly back to everything you've built this year: the if/else logic is identical to what you've now written in four different contexts (Arduino C++, Codecademy C++, Tracy, and plain Python) — only now it's controlling a physical-style input again instead of an abstract program.

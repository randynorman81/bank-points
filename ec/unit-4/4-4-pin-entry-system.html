4.4 — PIN Entry System

Two-period lesson, reuses your keypad from 4.3. This is the sprint's core logic — gets combined with the LCD in 4.6.

Intro

Ask AI these questions; look over the answers.

  1. How would a program compare a sequence of key presses against a stored correct PIN to decide whether access should be granted?
  2. Explain to a middle schooler why a PIN entry system needs to reset itself after each attempt, whether the attempt was correct or incorrect.
  3. Create a simple flowchart showing the decision process: enter digits, compare to stored PIN, grant or deny access, then reset.
  4. What happens to a real PIN entry system (like a door lock or ATM) if too many incorrect attempts are entered in a row? Why might that matter?
  5. Connect today's PIN comparison logic to something you already know how to do in code from earlier this course.
  6. Why might storing a PIN directly in your code be considered a security weakness in a real product, even if it works fine for a classroom project?

Notes

Look up these definitions and add them to your living glossary:

  • String comparison
  • Access control
  • Hardcoded value
  • Lockout

Key idea: use the String type (capital S) to compare your accumulated key presses against a stored correct PIN — String objects have built-in comparison methods. After every attempt (correct or not), reset the entered sequence so old digits don't bleed into the next attempt. Honest limitation: this build hardcodes the correct PIN directly in the code — fine for a classroom project, but a real security weakness in an actual product, since anyone reading the code (or firmware) would know the PIN instantly. A more security-conscious version tracks failed attempts and triggers a lockout after too many.

Assignments

  • 4.4 — PIN Entry System. Wire a single LED as an "access granted" indicator. Set a hardcoded 4-digit PIN. Accumulate key presses (from 4.3) and compare against the stored PIN once 4 digits are entered, lighting the LED only on an exact match. Then add reset logic so the sequence clears after every attempt, and distinguish correct vs. incorrect in the LED's behavior (e.g. solid vs. blink). Optional stretch: track consecutive incorrect attempts and add a simple lockout. Submit your annotated code and a photo of your working circuit.

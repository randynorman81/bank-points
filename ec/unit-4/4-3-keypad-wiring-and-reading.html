4.3 — Keypad: Wiring and Reading

Two-period lesson, new hardware: the 4x4 membrane keypad. Sprint 1 of the unit begins here.

Intro

Ask AI these questions; look over the answers.

  1. How does a 4x4 membrane keypad work internally? Why does it only need 8 wires to read 16 different keys?
  2. Explain to a middle schooler how a "row and column" grid can identify exactly which key was pressed, using something like a tic-tac-toe board as a comparison.
  3. Create a simple diagram showing a 4x4 grid of keys with rows and columns labeled, and how pressing one specific key creates one specific row-column connection.
  4. Why might a programmer use a library to read a keypad instead of writing the row/column scanning logic from scratch?
  5. Connect today's keypad to a real device you've used that has a similar keypad — what was it, and what was it used for?
  6. What is "debounce" in the context of buttons and keypads, and why might a single key press accidentally register as multiple presses without it?

Notes

Look up these definitions and add them to your living glossary:

  • Matrix keypad
  • Row/column scanning
  • Debounce
  • char array

Key idea: a 4x4 keypad's 16 keys sit at row/column intersections — one wire per row (4) + one per column (4) = 8 wires total, instead of 16 individual pins the Uno doesn't even have. Pressing a key connects its row to its column; the code scans each combination to find which key is down. A keypad library packages this scanning so you just call it. Each key press returns a single char (e.g. '5'); a char array accumulates several presses in sequence — direct prep for 4.4's PIN logic. Debounce filters the rapid, unintended multiple signals a mechanical key produces in its first few milliseconds — without it, one press can register as several.

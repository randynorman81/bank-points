6.1 — Classes & Objects

🔔 Bell Ringer — Think About It
  1. So far your programs have used separate variables to describe one thing (like separate red, green, blue variables for one RGB LED). A class lets you bundle those together as one object. Why might that be more organized?
  2. A class is like a blueprint, and an object is one specific thing built from that blueprint. What's a real-world blueprint you know of, and what are two different "objects" that could be built from it?
  3. If you were building a class to represent a student, what pieces of information (attributes) would it need to store?
  4. Why do you think most modern software (apps, games, websites) is built using classes and objects instead of one giant list of separate variables?

Notes

Look up these definitions:

  • Class
  • Object
  • Attribute (member variable)
  • Instance

Key idea: A class is a blueprint that bundles related data and behavior together, and an object is one specific instance built from that blueprint — like a Car class being the blueprint, and your specific car being one object made from it. Each object has its own attributes (the data it stores, like color or speed) that belong to that one instance. This is a fundamentally different way of organizing a program than separate variables for everything, and it's the foundation nearly all modern software is built on.

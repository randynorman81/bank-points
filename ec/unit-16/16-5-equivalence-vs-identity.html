16.5 — Equivalence vs. Identity

🔔 Bell Ringer — Think About It
  1. Two values can look equal (==) without being the exact same object in memory. Why might that distinction matter for a program?
  2. If two separate lists both contain [1, 2, 3], do you think they're == to each other? Do you think they're the same identity?
  3. Why might a program need to check identity (is the exact same object) rather than just equivalence (looks the same) in some situations?
  4. This connects back to the References & Pointers lesson from Codecademy's C++ course. What do you remember about how pointers relate to where something "lives" versus what it contains?

Notes

Look up these definitions:

  • Equivalence (==)
  • Identity (is)

Key idea: Equivalence (==) checks whether two values look the same, while identity (the is keyword) checks whether two variables actually refer to the exact same object in memory — two separate lists can both equal [1, 2, 3] (equivalent) without being the same object (not identical). This distinction connects directly back to References & Pointers from Codecademy's C++ course: identity is really asking "do these point to the same place," the same question a pointer answers in C++.

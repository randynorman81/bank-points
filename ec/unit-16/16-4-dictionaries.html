16.4 — Dictionaries

🔔 Bell Ringer — Think About It
  1. A list is accessed by numeric position (index 0, 1, 2...). A dictionary is accessed by a named key instead, like student["name"]. Why might named access be more useful for some kinds of data?
  2. If you were storing information about a student (name, grade, id number), would a list or a dictionary make more sense? Why?
  3. What real data have you worked with this year that's really a set of labeled fields, more than an ordered sequence (hint: think about the RGB color values from Unit 3)?
  4. Why do you think a dictionary is sometimes called a "key-value" structure?

Notes

Look up these definitions:

  • Dictionary
  • Key / value pair

Key idea: A dictionary stores key-value pairs, accessed by a named key instead of a numeric index — student["name"] instead of student[0] — which is a much better fit for data that's naturally labeled rather than strictly ordered, like a student's name, grade, and ID number all bundled together. This is conceptually close to the attributes you'd give an object in the Classes & Objects unit, just without needing to define a whole class for it.

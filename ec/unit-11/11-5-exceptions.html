11.5 — Exceptions

🔔 Bell Ringer — Think About It
  1. An exception is an error that happens while a program is running, like trying to convert "abc" to a number. Why might a program want to handle that gracefully instead of just crashing?
  2. try and except let a program attempt something risky and recover if it fails. Describe a real situation where you'd want a backup plan in case your first plan fails.
  3. If a program crashes every time a user types something unexpected, what does that say about how the program was written?
  4. Why do you think handling errors gracefully is considered a mark of professional-quality code?

Notes

Look up these definitions:

  • Exception
  • try / except
  • Error handling

Key idea: An exception is an error that occurs while a program is actually running — like trying to convert the text "abc" into a number, which Python can't do. Wrapping risky code in a try block, with an except block to handle the failure, lets a program recover gracefully instead of crashing outright. This matters most anywhere a program depends on unpredictable input, like a user typing something unexpected, or later, a sensor returning a value your code didn't plan for.

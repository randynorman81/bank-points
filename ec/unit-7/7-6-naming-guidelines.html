7.6 — Naming Guidelines

🔔 Bell Ringer — Think About It
  1. Why might a program with variables named a, b, and x be harder to understand than one with variables named speed, score, and playerName?
  2. Python has specific rules for what a variable name can contain. Why would a language enforce rules instead of allowing absolutely anything?
  3. If you had to name a variable that stores how many lives a player has left, what would you name it, and why is that name better than a vague one?
  4. Naming things well is considered a real professional skill in software engineering. Why do you think companies care about this instead of just caring whether the code works?

Notes

Look up these definitions:

  • Identifier
  • Naming convention
  • snake_case

Key idea: A clear, descriptive name turns code that only the original author understands into code anyone can read — playerScore is instantly understandable, x is not. Python variable and function names follow specific rules (they can't start with a number, can't contain spaces, and are case-sensitive) and a common style called snake_case, where words are separated by underscores, like total_score. This might seem like a small thing, but readable naming is one of the traits that separates professional code from a first draft.

Lighter vocabulary day — also worth a quick review of I2C vs. SPI, since it's easy to mix the two up.

I2CSPI
Wire count2 (SDA, SCL)4 (MOSI, MISO, SCK, SS)
Data wires1 shared, both directions2 separate, one each direction
AddressingShared address numberDedicated SS wire per device
SpeedGenerally slowerGenerally faster
Used here forLCD (4.5)RC522 (5.3)

The LCD doesn't need fast communication (text updates infrequently), so I2C's slower speed was fine; the RC522 needs faster, more frequent communication for reliable card reading, so SPI fit better — real protocol selection, the same principle as Lesson 5.9's motor selection. UART is a simpler, 2-wire, asynchronous protocol (no shared clock) best for simple point-to-point communication between exactly two devices — this course hasn't built with it, awareness-level only.

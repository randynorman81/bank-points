Notes

Look up these definitions:

  • Cloud server
  • Cloud architecture
  • API (Application Programming Interface)
  • Dashboard

Key idea: "the cloud" is just remote computers (servers), owned and maintained by a company, accessed over the internet — not some abstract, mysterious concept. Full path: sensor measures something → embedded device (Arduino) reads it → local network (WiFi) → internet (via your router) → cloud server (stores/processes it) → dashboard/app (a person actually sees it). An API is a defined, structured way for a device to request or send data to a cloud service — like a very specific form the device fills out every time, so the service knows exactly what to expect. None of this year's builds (traffic light, alarm, PIN entry, RFID lock) sent data anywhere beyond the local board — adding connectivity means a network connection plus code using an API. A well-designed IoT device should keep some local functionality even if its cloud connection drops.

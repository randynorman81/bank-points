3.2 — Case: Jeep Cherokee Hack

Notes

Look up these definitions:

  • Input validation

Background: in 2015, researchers Charlie Miller and Chris Valasek remotely accessed a Jeep Cherokee through its internet-connected entertainment system (Uconnect), then reached the vehicle's transmission, steering, and brakes — while it was being driven on a highway. This led to a recall of roughly 1.4 million vehicles. The entertainment system's connection to the cellular network and its overly-close connection to critical vehicle systems created an oversized attack surface. Without input validation, the vehicle's internal systems accepted commands they never should have received from an external source. This is a preview of this unit's whole theme: every sensor lab from here reads data and reacts to it — is that data trustworthy?

    Connected cases for Section 8: Boeing 737 MAX MCAS Failures (2018–2019) — a single angle-of-attack sensor with no redundancy fed bad data to an automated flight control system, which repeatedly forced the nose down; 346 people died across two crashes. Uber Self-Driving Fatality (Arizona, 2018) — the car's sensors detected a pedestrian about 6 seconds before impact, but the software kept reclassifying what it saw and never braked; the sensor data was accurate, the system's trust of it was the failure. For Section 8: what connects all three cases — a connectivity vulnerability, a lack of sensor redundancy, or a software interpretation failure? What does this reveal about trusting sensor or remote input data in safety-critical systems?

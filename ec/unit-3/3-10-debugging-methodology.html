3.10 — Debugging Methodology

A discussion and guided-practice day — direct preparation for your independent V1/V2 build next lesson.

Intro

Ask AI these questions; look over the answers.

  1. What is systematic debugging, and why is changing one thing at a time considered such an important rule when fixing code?
  2. Explain to a middle schooler what Serial Monitor is used for when debugging, beyond just showing sensor readings.
  3. Create a simple checklist someone could follow, in order, when their code isn't working as expected — starting with the most likely problems first.
  4. What is a race condition, and how does it connect to a case we studied earlier this year?
  5. What is an interrupt in programming, and how is it different from a program that only checks things inside its main loop?
  6. Why might professional engineers consider debugging skill to be just as important as writing code in the first place?

Notes

Look up these definitions and add them to your living glossary:

  • Systematic debugging
  • Infinite loop
  • Logic error
  • Interrupt

Note: race condition is not a new term today — you already added it back in Lesson 1.2 (Therac-25). Find your existing entry and update its Comfort Rating instead of adding a new row; now that you've written real code, you understand it more concretely.

Debugging checklist: (1) did the code actually upload, or is an old version still running? (2) any syntax error the IDE is flagging? (3) print the relevant variable's value right before the problem — is it what you expected? (4) check comparison operators — == not =? (5) check wiring matches your code's pin references. (6) if a sensor needs warm-up time, has it had it? A logic error is code that compiles and runs but does the wrong thing — harder to find than a syntax error since nothing crashes. An interrupt lets a microcontroller instantly pause and respond to something (like a button press) without waiting for the current loop to finish — useful for anything needing an instant response; you won't write interrupt code this course, just understand why it exists.

3.8 — Test and Debug

🔔 Bell Ringer — Think About It
  1. A bug is when a program does something different than you wanted. Describe a time technology did not work and how you figured out why.
  2. Why is changing five things at once a bad way to fix a problem?
  3. Serial.println lets a program tell you what it is thinking. What might you print to find out if a button is really being pressed?
  4. A multimeter measures voltage in a circuit. Why would measuring be better than guessing?

Notes

Look up these definitions:

  • Bug
  • Serial Monitor
  • Multimeter
  • Troubleshooting

Key idea: Debugging is a process, not a guess: (1) say what should happen, (2) say what does happen, (3) print values with Serial.println, (4) measure with the multimeter (set it to DC voltage and touch the two points you want to compare), (5) change one thing at a time and test again. Bugs come in two flavors, wiring bugs (wrong pin, backwards part, missing resistor) and code bugs (wrong pinMode, missing Serial.begin, wrong pin name), and you need to check both.

3.9 — Temperature Sensor Lab + Functions

Two-period lesson, new sensor: the DHT11 (temperature + humidity). Also the first time you write your own function.

Intro

Ask AI these questions; look over the answers.

  1. What is the DHT11 sensor and what two things does it measure at the same time?
  2. What is a function in programming, and why would a programmer create their own function instead of just writing the same code over and over wherever it's needed?
  3. Create a simple visual showing a function being "called" from multiple places in a program, each time running the same packaged block of code.

  6. What real products combine temperature and humidity monitoring the way the DHT11 does?

Notes

Look up these definitions and add them to your living glossary:

  • Function
  • Function call
  • Return value
  • Humidity

Key idea: the DHT11 measures temperature and humidity together, using a timing protocol complex enough that you'll use a library (dht.readTemperature(), dht.readHumidity()) instead of a raw digitalRead/analogRead. A function is a named, reusable block of code — you've been calling built-in ones (analogRead, digitalWrite, pulseIn) all course, but today you write your own: float getTemperature() { return dht.readTemperature(); } then call it with float currentTemp = getTemperature();. The return value is the data it hands back. A function only runs when called by name; a loop repeats automatically — they often work together.

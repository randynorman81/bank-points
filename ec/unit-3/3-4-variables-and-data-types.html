3.4 — Variables and Data Types (Real Hardware)

🔔 Bell Ringer — Think About It
  1. A physical potentiometer lets someone change your program's behavior in real time, just by turning a knob — no re-uploading code required. Why is that a fundamentally different kind of "variable" than one you hardcode and change by editing your sketch?
  2. analogRead() returns a value from 0–1023, but delay() expects milliseconds, not a 0–1023 number. What has to happen to the raw potentiometer reading before it can usefully control your blink timing?
  3. If you turn the potentiometer while the Arduino is mid-blink, your LED's timing changes on the very next loop, not instantly. Why does that lag exist, and is it actually a problem?
  4. A boolean variable can only ever be true or false. A potentiometer reading can be any of 1024 different values. Why does the real world mostly need more than just true/false?

Notes

Look up these definitions:

  • Potentiometer
  • analogRead()
  • map()

Key idea: in 2.4, a variable controlled your blink timing, but you still had to edit code and re-upload to change it. Today, wire a real potentiometer to an analog input pin and read it live with analogRead(pin) — a value from 0 to 1023. Use map(value, 0, 1023, 100, 2000) to convert that raw reading into a usable millisecond range, then feed the result straight into delay(). Now turning the knob changes your blink speed live, with no re-upload — a variable whose value comes from the physical world instead of your code.

Test and Debug: Break It, Then Fix It

Notes for the 3.8 assignment: build a circuit that is broken in at least 3 places, show what is wrong, then fix it. What makes a good bug, a 5-step method for finding bugs, a live lab with real bugs to hunt, and how to write a bug report.

LIVE

Live Lab: Hunt the Bugs

Try it right here

Three LEDs that are supposed to blink together. Press Start to see them work. Then click a bug button (or an experiment) and use the 5-step method to work out what is wrong and why. The goals tick off when you have seen each bug in action.

01

What Makes a Good Bug?

Part 1

Your job is to break the program on purpose, in ways that compile and run but do the wrong thing. Some bugs live in the parts and some in the code. Click each idea to see if it counts.

Do not use a missing bracket or a typo that stops the program from compiling. Those just show a red error. The point is bugs that look fine and still misbehave.
02

The 5-Step Debugging Method

Part 2 + Reflections

A detective does not arrest the first suspect. They list what should have happened, what did happen, collect evidence, and test one theory at a time. Click each step.

Never change several things at once. If it starts working you will not know which change fixed it, and if it gets worse you will not know which one broke it.
03

Writing It Up

Break It + Fix It

A good bug report has three parts. Here is one for a bug that is not in your circuit, as an example. In 3.8 you write three of these: first just what is broken (Break It), then how you fixed it (Fix It).

Symptom (what you saw)CauseFix
The buzzer from 3.2 was silent the whole time.The code used tone(7, 440), but the buzzer was wired to pin 8.Changed the code to tone(8, 440).
The servo from 3.3 did not move at all.The code never ran myServo.attach(9); in setup().Added the attach line.

Break It (3.8, part 1)

Build 3 or more LEDs. Hide at least 3 bugs: some in the parts, some in the code. Run it, write down exactly what is broken (which LED, which line).

Fix It (3.8, part 2)

Bring your broken project over with Start from my circuit, fix all three, and write how you fixed each one. Every LED must work, and none may be backwards or burned out.

Test yourself

Guessing is slow. Evidence is fast.

Say what should happen, see what does, check the circuit, check the code, and change one thing at a time.

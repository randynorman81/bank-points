RGB LEDs and Color Mixing

Everything you need for the 3.1 assignment: how an RGB LED works, wiring it, your first custom function (setColor), mixing colors with numbers, and the fading challenge.

01

Three LEDs in One Bulb

Look closely at your phone screen with a magnifying glass and you'll see it isn't made of colors at all. It's made of tiny red, green, and blue lights. Every color you've ever seen on a screen is those three, mixed. An RGB LED is one of those pixels you can hold.

4 legs, 1 shared

Three legs are the colors: red, green, blue. The fourth, the longest, is shared by all three. In Tinkercad it's called the common cathode, and it connects to GND.

Tip: in Tinkercad, hover your mouse over any leg and a label pops up telling you what it is. Always check the label before you wire. (The order of the legs in the drawing is common, but always trust the label.)

02

Wiring It

Part 1

Each color is its own little LED, so each color follows the same rule as every LED since 2.2: its own resistor, its own pin.

LED legWhere it connects
Red220 Ω resistor, then Arduino pin 9
Green220 Ω resistor, then Arduino pin 10
Blue220 Ω resistor, then Arduino pin 11
Longest leg (common cathode)GND
Why 9, 10, and 11? All three have a ~ next to them: they're PWM pins (2.5). That's what lets each color be dim or bright instead of only on or off. Put the RGB LED on the breadboard so each of its 4 legs is in a different row.
03

The Code, and Your First Function

Part 2

You could write three analogWrite() lines every time you want a new color. Or you can teach the Arduino a new word, setColor, that does all three at once.

const int RED = 9; // const = this number never changes const int GREEN = 10; const int BLUE = 11; void setup() { pinMode(RED, OUTPUT); pinMode(GREEN, OUTPUT); pinMode(BLUE, OUTPUT); } void setColor(int r, int g, int b) { // BETWEEN setup() and loop() analogWrite(RED, r); analogWrite(GREEN, g); analogWrite(BLUE, b); } void loop() { setColor(255, 0, 0); delay(1000); // red setColor(0, 255, 0); delay(1000); // green setColor(0, 0, 255); delay(1000); // blue }

Reading the function

  • void: it does a job but doesn't hand anything back.
  • setColor: the name you made up.
  • (int r, int g, int b): three parameters, slots for the numbers you pass in.
  • setColor(255, 0, 0) fills r = 255, g = 0, b = 0, then runs the three lines inside.

Tinkercad setup

Click Code, then switch the view from Blocks to Text. Delete what's there and build your code in order. Put setColor between setup() and loop(), not inside either one.

05

The Fade Challenge

Step 5 (required)

Jumping from red to blue is easy. Gliding between them means passing through every color in between, one tiny step at a time. That's a job for a loop that counts.

A counting for loop

for (int i = 0; i <= 255; i++) { // i is 0, then 1, then 2 ... up to 255 }

Start at 0; keep going while i is 255 or less; add 1 each time. Whatever's inside runs 256 times, and i is a different number every time.

The hint from your assignment

Put the counter in one setColor number, and its opposite, 255 minus the counter, in another. As one color goes up, the other goes down by the same amount. Add a short delay inside the loop so you can see it glide.

06

Light Mixes Differently Than Paint

Reflection 1

Mix every paint color together and you get a muddy brown-black. Mix every light color together and you get white. Same idea of "mixing," opposite results. Here's why.

Light: additive

Each colored light adds more light that reaches your eye. More colors = more light = brighter, all the way to white. Red, green, and blue are the primaries.

Paint: subtractive

Paint doesn't make light; it absorbs (subtracts) some colors and reflects the rest. Each paint you add absorbs more, so less light reflects back. More paint = darker.

Reflection 2: think about what your loop() would look like if you had to write out three analogWrite() lines for every single color, including all the colors in your fade.

Test yourself

Three numbers, three pins, one bulb, sixteen million colors.

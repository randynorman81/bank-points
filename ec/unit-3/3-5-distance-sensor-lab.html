3.5 — Distance Sensor Lab

Two-period lesson, first real hardware sensor of the unit — the HC-SR04 ultrasonic sensor and the buzzer.

Intro

Ask AI these questions; look over the answers.

  1. How does an ultrasonic distance sensor like the HC-SR04 actually measure distance? What is it sending out and listening for?
  2. Explain to a middle schooler how echolocation works, using bats or dolphins as an example, before connecting it to how the sensor works.
  3. Create a simple diagram showing sound waves traveling from the sensor to an object and back, with the round-trip time being used to calculate distance.
  4. Why might a distance sensor occasionally give an inaccurate or "noisy" reading? What real-world conditions could cause this?
  5. Connect today's distance sensor to a real product I might recognize — where is this exact kind of sensor used in cars, robots, or other devices?
  6. If a self-parking car's distance sensor gave a wrong reading at the wrong moment, what could happen?

Notes

Look up these definitions and add them to your living glossary:

  • Ultrasonic sensor
  • Echolocation
  • pulseIn()
  • Sensor noise

Key idea: the HC-SR04 sends a burst of ultrasonic sound and times how long it takes to bounce back — this is echolocation, the same principle bats and dolphins use. Distance = (speed of sound × time) ÷ 2 (divided by 2 because the timed trip is out AND back). pulseIn() measures how long the echo pin stays HIGH, in microseconds. Readings can be noisy — soft or angled surfaces scatter the sound, multiple objects can create confusing echoes. Treat raw sensor data as imperfect, same theme as the Jeep Cherokee case.

Assignments

  • 3.5 — Distance Sensor Lab. Wire the HC-SR04 (VCC→5V, GND→GND, TRIG/ECHO to digital pins), use pulseIn() to measure echo duration, convert to a distance, and print it to Serial Monitor. Verify accuracy with a ruler at a few known distances. Then wire an active buzzer and add if/else logic so it sounds when something gets closer than a threshold you choose (e.g. 20cm). Debug any noisy or random triggering — check your comparison operator and threshold before assuming the hardware is broken. Submit your annotated code and a photo or short video of the working alert system.

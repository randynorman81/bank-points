3.11 — V1 and V2 Alarm System

Independent build, two periods. Your first V1/V2 iteration of the year — a preview of the Scrum framework coming in Unit 4.

Intro

Ask AI these questions; look over the answers.

  1. What does "V1" and "V2" mean in product development, and why do engineers build a basic working version before adding improvements?
  2. Explain to a middle schooler why it's smarter to get something simple working first, rather than trying to build the complete, advanced version all at once.
  3. Create a simple comparison showing what a "V1" alarm system might do versus what a more advanced "V2" version of the same system might add.
  4. What are some real alarm or security systems that combine more than one type of sensor? Why might combining sensors be more reliable than using just one?
  5. Connect today's task — building a working version, then improving it — to a skill or hobby where you also got the basics working before adding more advanced techniques.
  6. If you were designing a home security alarm from scratch, what would you prioritize first, and what would you consider an upgrade for later?

Notes

No new vocabulary today.

What you're building: an alarm using any sensor (or combination) from this unit — photoresistor (simulation), HC-SR04, PIR, or DHT11 — plus your buzzer. There's no "best" sensor choice; a simple, reliable single-sensor alarm beats an ambitious one that doesn't work. V1 requirements: a working alarm that detects a condition and triggers the buzzer, using if/else correctly, fully debugged. V2 requirements: a genuine, specific improvement on V1 — not cosmetic. Acceptable examples: a second sensor for combined detection, Serial Monitor logging of every trigger, a reset mechanism, or the loop-based averaging technique from 3.6 to reduce false triggers. Not a day for AI to generate your solution — using it to debug a specific error is fine.

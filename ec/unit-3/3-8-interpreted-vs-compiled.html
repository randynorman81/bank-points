3.8 — Interpreted vs Compiled: Timing Your Own Board

🔔 Bell Ringer — Think About It
  1. You've read that compiling happens "fast" on a microcontroller. Today you'll actually time it with a stopwatch. Why might putting a real number on something you'd normally just accept as true change how well you understand it?
  2. If a bigger, more complex sketch takes longer to compile and upload than a tiny one, what does that tell you about what "compiling" is actually doing behind the scenes?
  3. Every lesson so far, clicking Upload has felt instant enough to not think about. Now that you're timing it, do you think that upload delay would matter for any real device you can think of?
  4. Python (interpreted) runs immediately with no separate compile step. If Arduino worked that way, what do you think would happen to today's timing experiment?

Notes

Look up these definitions:

  • Interpreted language
  • Compiled language
  • Compiling

Key idea: same distinction as 2.8 — Arduino's C++ is compiled all at once before it runs, which is faster and more predictable on a microcontroller than an interpreted language reading code line by line. Today, instead of only researching the idea, time it yourself: use a stopwatch to measure your own board's real compile+upload cycle for a few of your own sketches from this unit — Blink, then a longer one like 3.6's button-and-sequence code. Log the real numbers side by side. This turns an abstract claim ("compiling is fast, but not instant") into something you actually measured with your own hardware.

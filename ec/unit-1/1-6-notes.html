NOTES 1.6  /  SUBJECT: WHERE THE THINKING HAPPENS

The Double Life of a Raspberry Pi

Six terms, one real design question underneath all of them: when a device "thinks," where does that thinking actually happen — and is the board it's running on even a dedicated embedded system in the first place?

⏰ 6 min read  ·  🧠 4 core concepts  ·  📋 15 real-world examples
Single-Board Computer

General-purpose

A complete computer on one board, running a full operating system that can multitask — browse the web, run a server, and log data all at once.

Example: A Raspberry Pi running a home media server, file share, and website simultaneously.

Edge AI

On the device

Thinking happens directly on the device itself — fast, private, and it still works with zero internet connection.

Example: A smart camera recognizing a face without ever sending the image anywhere.

Cloud AI

On a server

The device sends its data over the internet to a powerful remote server, which does the thinking and sends an answer back.

Example: A voice assistant sending your question to a server for a full answer.

00

One Board, Two Identities

A Raspberry Pi is genuinely both things this course has talked about all unit — a general-purpose computer and a dedicated embedded system — depending entirely on how it's set up. The chip never changes. What changes is the job you give it.

As a single-board computer

Boot it into a full desktop OS (usually Linux), and a Raspberry Pi behaves exactly like a tiny general-purpose computer: a file system, a browser, multiple programs running at once, a user who can install anything they want, any time. This is the same definition of "general-purpose" you've used since Lesson 1.1, just shrunk onto a board the size of a deck of cards.

As an embedded system

Strip the desktop away, boot it straight into one dedicated program, and give it exactly one job to do forever — and that same board is now a real embedded system by the strict definition: purpose-built, not user-reconfigurable, running one fixed task decided at design time.

This is exactly why the Raspberry Pi is worth studying on its own: unlike an Arduino (which is always an embedded microcontroller) or a laptop (which is always general-purpose), the Pi can genuinely be either one — and real products make that choice on purpose, for real engineering reasons.
01

What Counts as AI?

Two terms get used almost interchangeably, but they're not the same thing — one is the category, the other is the technique that makes most of today's AI actually work.

Artificial Intelligence

A broad field — any computer system built to do something that normally requires human-like judgment: recognizing a face, understanding speech, predicting what you'll type next. It's a category, not one specific technique.

Machine Learning

The technique behind almost all modern AI. Instead of a human writing an explicit rule for every situation, the system is shown a large number of examples and learns the pattern itself — pattern-finding from data, instead of hand-written rules.

02

Edge AI vs. Cloud AI

Once you've got a trained model, it has to run somewhere. That's the real design decision for anyone building an AI-powered embedded device — and it's a tradeoff, not a clear winner.

Edge AICloud AI
Where it thinksDirectly on the device itselfOn a remote server, over the internet
SpeedFast — no round trip over a networkSlower — data has to travel there and back
PrivacyStronger — nothing has to leave the deviceWeaker — your data is sent somewhere else
Processing powerLimited by the device's tiny chip and batteryEffectively unlimited — real data centers
Works offline?YesNo — needs an internet connection
Most real products aren't purely one or the other. A lot of devices do something simple and fast on the edge (like noticing a face is present at all) and hand off anything that needs real reasoning to the cloud (like figuring out whose face it is, or answering a spoken question).
Edge AI · 5 Examples
01

Phone face/fingerprint unlock

Your face scan is matched against your stored face data right on the phone's chip. Biometric data staying on-device instead of a server is a real security requirement, not a nice-to-have.

02

Smart doorbell person-detection

Before it ever sends a notification, the camera decides locally: person, car, or just a tree branch? Filtering on-device saves data plans and server costs.

03

Self-driving car object detection

Recognizing a pedestrian or a braking car has to happen in milliseconds — a cloud round-trip is too slow at highway speed.

04

Voice assistant wake-word detection

Catching "Hey Siri" runs locally on purpose — streaming every sound in your house to a server just to catch its name would be a privacy and battery problem.

05

Factory equipment vibration monitoring

A sensor has to notice an abnormal vibration the instant it starts. Factory floors don't always have reliable internet either.

Cloud AI · 5 Examples
01

Voice assistants answering open questions

A question that actually requires reasoning gets routed to a server running a massive language model — far too large to fit on a speaker or phone.

02

Streaming recommendation engines

Netflix or Spotify compares your habits against millions of other users at once. No single device could store or process a dataset that size.

03

Photo library content search

Searching "dog at the beach" across years of photos is far more storage and processing than a phone can do continuously.

04

Large-scale email spam filtering

Catching a new phishing scam depends on patterns seen across millions of inboxes at once, updated constantly. Only a central server sees enough traffic.

05

AI-assisted medical image analysis

Helping a radiologist spot something on a scan runs on an extremely large, carefully validated model needing continual retraining.

03

Embedded AI

Embedded AI is what you get when a trained Machine Learning model is shrunk down to actually fit and run on a small, dedicated embedded system — the exact kind of device you defined back in Lesson 1.1: a computer system built into a larger device to do one specific job, not a general-purpose computer.

Embedded AI overlaps with edge AI — both mean "thinking happens locally." The difference is what kind of device it's running on: edge AI can run on a phone or laptop, general-purpose computers with power to spare. Embedded AI specifically means a tiny, dedicated, single-purpose chip, usually with real-time constraints a phone never has to worry about.
Embedded AI · 5 Examples
01

Learning thermostats

A small dedicated chip in the wall learns your household's patterns and adjusts automatically — it has to keep working even if your Wi-Fi goes down.

02

Fall detection on a smartwatch

Recognizing a hard fall has to happen instantly, on the watch's own chip, because the moment it matters most is exactly when a cloud connection can't be counted on.

03

Pacemaker rhythm monitoring

An AI-assisted pacemaker has to notice an irregular heartbeat and react within a fraction of a second, inside the body — no version of this waits on a network request.

04

Robot vacuum obstacle recognition

Telling a wall apart from a pet has to happen continuously and cheaply on a small onboard chip, not a full general-purpose computer.

05

Hearing aid noise cancellation

Cleaning up background noise has to happen with essentially zero delay, on a chip small enough to fit in the ear, running for days on a tiny battery.

04

Putting It Together

Today's Build Proposal Dossier asks you to design two real Raspberry Pi projects and classify how each one thinks. Work through these in order for each build.

Every real Pi project is a design decision someone made on purpose — both which identity to give the board, and where to put the thinking. Your job today is to make those same two decisions yourself, and defend them.

Decide the identity

  • Does this project need to multitask, run a full OS, or let a user install new software later? That's single-board-computer territory.
  • Does it boot into exactly one job and never need to be anything else? That's embedded-system territory.
  • What would the project lose by picking the other identity instead?

Decide where it thinks

  • Does this project involve any AI or machine learning at all — or is it just sensors and logic?
  • If there's AI, does it still work with the internet unplugged? (Edge.) Does it stop working without a connection? (Cloud.)
  • What's the tradeoff behind that choice — speed and privacy, or raw power?

The chip doesn't care which identity it's given, or where the thinking happens. The engineer building it always has to.

Every real Raspberry Pi project made both of these decisions on purpose. Today's Build Proposal Dossier asks you to make them yourself, twice, and defend both.

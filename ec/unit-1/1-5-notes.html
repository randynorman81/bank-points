Read This Before You Play

The Smart City Simulator throws 8 real engineering ideas at you across 20 decisions. None of them are optional background — every one of them is the actual reason two options in the game look different from each other. Read through all 8 before you open the simulator.

00

The Core Tradeoff Vocabulary

Almost every decision in the simulator is really the same three-way tug-of-war, just wearing a different costume each time.

Data granularity

How fine-grained or detailed a piece of collected data is. A water meter that reports usage once a day has low granularity; one that reports every 15 minutes has high granularity — detailed enough to reveal exactly when someone showers, does laundry, or is away from home.

Shows up directly in: Water Meters, School Bus GPS Tracking

Centralized system

A system where one central point — one database, one server, one control room — holds the data or the control for everything underneath it. Centralizing makes a system easier to manage and search, but it also means one point of failure can affect everything connected to it at once.

Shows up directly in: Traffic Cameras, Digital Permits, Security Patch Policy

Attack surface

Every possible point where an outside attacker could try to get in — every network connection, every login, every device that talks to the outside world. More connected features usually mean a bigger attack surface, even when each individual feature seems harmless.

Shows up directly in: City Hall Thermostats, Public Wi-Fi, Emergency Alert System
01

Design Choices That Reduce Risk

None of these make a system perfectly safe. They're deliberate engineering choices that trade some speed or convenience for a smaller, more contained risk.

Edge computing (on-device processing)

Processing data right where it's collected — on the device itself — instead of sending it somewhere else first. A camera that decides "that's a red-light violation" using its own onboard chip, instead of sending raw video to a central server for review, is doing edge computing.

Shows up directly in: Traffic Cameras, Noise-Level Sensors, Code Enforcement Body Cameras

Air-gapped

A system that is physically disconnected from any outside network — not firewalled, not "hard to reach," but not connected at all. The only way to change an air-gapped system is to be physically present at it. It's inconvenient by design, on purpose.

Shows up directly in: Water Treatment Plant Control System

Security by design

Building security into a system from the very first decision, instead of adding it on afterward as a patch. A staggered, tested update rollout is security by design; auto-updating everything overnight because it's faster to build is the opposite.

Shows up directly in: Security Patch Policy, Power Grid Substation Control
02

When It All Goes Wrong

One more term ties the whole simulator together — and it's the same idea you already studied earlier this unit.

Single point of failure

Any one part of a system that, if it fails or gets compromised, takes down or exposes everything depending on it — with nothing else in place to catch the failure. A city where every device trusts the same central update server has built a single point of failure, even if every individual decision that led there seemed reasonable on its own.

Shows up directly in: Security Patch Policy, Power Grid, Water Treatment, Emergency Alert System, Traffic Cameras
You already met this idea in the Therac-25 case: removing a second, independent safeguard and trusting one system to catch everything is exactly how a single bug becomes a citywide disaster. Watch for it while you play — a few of the simulator's 20 decisions are quietly connected to each other in exactly this way.

Eight ideas, twenty decisions, one city that has to live with all of them at once.

None of these terms are abstract once you're the one making the call. Keep them in mind as you play — and again when you sit down to write about which decisions actually mattered most.

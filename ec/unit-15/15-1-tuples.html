15.1 — Tuples

🔔 Bell Ringer — Think About It
  1. A tuple stores an ordered list of values but, like a string, can't be changed once created. Why might you want a list of values that's guaranteed to never change?
  2. If a tuple stored a coordinate pair like (3, 5), why might immutability actually make sense for something like a fixed location?
  3. How is a tuple similar to the vectors you used in Codecademy's C++ course, and how is it different?
  4. What real-world data could you imagine storing as a tuple, where you'd never want it to change once set?

Notes

Look up these definitions:

  • Tuple
  • Immutable data structure (review)

Key idea: A tuple stores an ordered sequence of values, accessed by index just like a string or a vector, but like a string, it's immutable — once created, it can't be changed. This makes tuples a good fit for data that should never accidentally be modified, like a fixed coordinate pair (3, 5) or a set of RGB color values. It's the same core idea as the vectors from Codecademy's C++ course, but with the added guarantee that the data stays exactly as it was created.

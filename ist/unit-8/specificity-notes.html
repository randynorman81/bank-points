Selectors and Specificity

When two rules fight over the same element, the more specific one wins. Learn the ranking, and how to aim a selector precisely.

tag @CHIP@lt; class @CHIP@lt; id @CHIP@lt; inline
01

When Two Rules Disagree

A teacher says "everyone wear a uniform." Your coach says "wear the team jersey today." Who do you listen to? The more specific instruction wins. CSS settles arguments the same way. When two rules both style the same thing, the more specific one wins, no matter which came first. This ranking is called specificity.

WEAKESTTag rule: p speaks to every paragraph.
STRONGERClass rule: .name speaks to a group.
STRONGER STILLId rule: #name speaks to one element.
STRONGESTInline style written right on the tag.

Build the fight. Switch rules on and off and see which color the paragraph ends up with.

02

Two Classes on One Element

Think of a locker with two stickers: one for your team, one for your grade. Each sticker adds its own meaning. An element can wear more than one class too. List them in the same class attribute, separated by a space, and every class rule that matches applies.

Click the stickers to add or remove classes from the card.

The element's class attribute

This paragraph is wearing...

Wrong: two class attributes

<p class="big" class="red">

The second one gets ignored.

Right: one attribute, names separated by a space

<p class="big red">

Both rules apply. No commas.

03

Combining Selectors

Sometimes one selector is too broad. "Every student" is too many people, but "every student on the soccer team" is exactly who the coach means. Selectors can be combined to aim more precisely.

04

Why Inline Styles Are Avoided

An inline style is a trump card. It beats class rules and id rules in your stylesheet. That sounds powerful, but it is a trap: if one element has an inline color, your CSS file can never change it again without hunting it down in the HTML. Real teams keep style rules in the stylesheet so one file stays in charge.

Rule of thumb: use tag rules for the basics, classes for looks you reuse, ids for the one-of-a-kind element, and skip inline styles.

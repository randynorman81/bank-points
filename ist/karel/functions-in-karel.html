Functions in Karel (and the Main Function)

A function is a name you give to a group of steps, so you can reuse them without retyping them. This is the single most important idea in this whole unit — and the main() function is where every program actually begins.

00

What Is a Function?

A function is a named group of commands that you define once and can run ("call") as many times as you want, just by using its name.

function turnRight() { turnLeft(); turnLeft(); turnLeft(); }

This defines a brand new command called turnRight() — it doesn't exist in Karel by default, so you build it out of the three turnLeft(); calls from Lesson 3. Once it's defined, you can use turnRight(); anywhere in your program, as many times as you want, and it will always do those same three turns.

Defining a function

function means "I'm about to describe a new function." function turnRight() { says "here's a new command named turnRight." Everything between the curly braces { } is what that command actually does.

Calling a function

Once it's defined, typing turnRight(); anywhere else in your program runs those three lines — without you having to write them out again.

Function names are written in camelCase — no spaces, no underscores, each new word capitalized after the first: turnRight, not turn_right or TurnRight. Stick to this every time you name your own function.
01

The Main Function: Where Your Program Actually Starts

Once you start writing your own functions, every program needs one special function that Karel always runs first: main(). Think of it as the "start button" — no matter how many other functions you've written, Karel only ever begins by running what's inside main().

function turnRight() { turnLeft(); turnLeft(); turnLeft(); } function main() { move(); turnRight(); move(); putBall(); }

Notice turnRight() is defined above main(), but it only actually runs when main() calls it. CodeHS reads your whole file top to bottom to learn what functions exist, but it only starts doing anything once it reaches main().

Rule to remember: if a command isn't inside a function that main() eventually calls, it never runs — no matter where it's written in the file.
02

Why Bother With Functions At All?

Reason 1

Less typing

Write the three turnLeft(); calls once, use turnRight(); a hundred times.

Reason 2

Fewer mistakes

If turnRight(); has a bug, you fix it in exactly one place — not everywhere you copy-pasted those three lines.

Reason 3

Easier to read

turnRight(); reads like plain English. Three raw turnLeft(); calls make a reader stop and figure out what they add up to.

Real-life comparison: think of a function like a nickname for a whole routine — "get ready for school" secretly means "brush teeth, get dressed, eat breakfast, grab backpack." You don't re-explain all four steps every morning; you just say the nickname.
03

Common Mistakes

Mistake 1

Forgetting the parentheses

turnRight // missing ()

A function name always needs () after it to actually call it, even if it takes no extra information.

Mistake 2

Writing commands outside of any function

Every command has to live inside a function — usually main() or a function that main() calls. Loose commands floating outside a function will cause errors.

Mistake 3

Forgetting a curly brace

Every { needs a matching }. Forgetting the closing brace is one of the most common errors you'll see — if CodeHS says there's a problem but the line number looks fine, count your braces first.

A function is a name for a group of steps. main() is the one function that always runs first.

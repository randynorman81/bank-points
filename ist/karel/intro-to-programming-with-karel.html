KAREL NOTES  /  LESSON 1

Introduction to Programming with Karel

Meet Karel: a robot dog who lives on a grid and only does exactly what you tell it. This is where you learn what "writing a program" actually means — one simple command at a time.

00

What Is Karel?

Karel is a robot that lives in a grid of streets and avenues, kind of like city blocks seen from above. Karel can move around, turn, and pick up or drop little balls (sometimes called beepers). You control Karel by typing commands, one at a time, and Karel does exactly what you say — no more, no less.

Karel (the triangle) facing up, a wall on the right side of one square, and a ball (the dot) sitting on a corner.

Why start with a robot on a grid? It lets you focus on one big idea — giving a computer exact, in-order instructions — without needing to learn a bunch of confusing typing rules first. Everything you learn moving Karel around carries directly over to real code later this year.
01

Karel's Four Starter Commands

These four commands are all you need to get Karel moving and interacting with the world. Every Karel program you write is built out of these.

CommandWhat it does
move();Moves Karel forward exactly one square in the direction it's currently facing
turnLeft();Turns Karel 90° to the left, without moving forward
putBall();Drops a ball on the corner Karel is currently standing on
takeBall();Picks up a ball from the corner Karel is currently standing on
Notice every command ends with a semicolon ; — that's how CodeHS's Karel knows where one instruction ends and the next begins. Get used to typing it; you'll do it after almost every line this year.
Important: Karel does not have a turnRight(); command built in! That's on purpose — you'll learn why, and how to work around it, in Lesson 3.

Your first program

move(); move(); turnLeft(); move(); putBall();

Read this out loud like a set of directions: "Walk forward two squares. Turn left. Walk forward one more square. Drop a ball." Karel runs each line exactly in the order you wrote it, top to bottom.

02

Order Matters — A Lot

Karel has no common sense. It cannot guess what you "meant." It runs your commands in the exact order you wrote them, and nothing else.

This works

move(); then turnLeft(); then move(); — Karel walks forward, turns, then walks forward again in the new direction. Three separate, clear steps.

This does NOT do the same thing

turnLeft(); then move(); then move(); — Karel turns first, then walks forward twice in the new direction. Same three commands, different order, completely different result.

Rule of thumb: before you write any commands, picture the path in your head first, or even sketch it on paper. Programmers plan the steps before typing them — you'll do this constantly this year.
03

Common Mistakes

Mistake 1

Running Karel into a wall

move(); // wall right there!

If there's a wall directly in front of Karel and you call move(); anyway, the program crashes. Always check the map before you write move();.

Mistake 2

Miscounting squares

move(); move(); move();

It's easy to write one too many or too few move(); calls. Count the squares on the map carefully before typing.

Mistake 3

Forgetting Karel only turns left

If you need Karel to face right, you can't just write "turn right" — there's no such command yet. More on this in Lesson 3.

Four commands, run in exact order. That's the whole idea behind every program you'll ever write.

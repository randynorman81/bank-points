If Statements and Conditionals

Up to now, Karel has done the exact same thing every time. An if statement lets Karel look at its surroundings and make a decision — do this, only if this is true.

00

What Is a Condition?

A condition is a yes-or-no question. In code, the answer is either true or false — nothing in between. Karel has several built-in questions it can ask about the world around it.

ConditionQuestion it answers
frontIsClear()Is there NOT a wall directly in front of Karel?
frontIsBlocked()IS there a wall directly in front of Karel?
leftIsClear() / rightIsClear()Is there no wall to Karel's left / right?
ballPresent()Is there a ball on Karel's current corner?
noBallPresent()Is Karel's current corner empty?
Notice the pattern: each condition is a question, and it always answers true or false — it never moves Karel or changes anything by itself. Asking frontIsClear() doesn't move Karel; it just checks.
01

The If Statement

An if statement runs a block of code only when its condition is true. If the condition is false, that block is skipped entirely.

function main() { if (frontIsClear()) { move(); } }

Read it like a sentence: "if the front is clear, move." If there happens to be a wall right in front of Karel, move(); never runs, and the program just continues on to whatever comes after the if statement — no crash.

Why this matters: without an if statement, you'd have to know in advance exactly what's in front of Karel every time. With one, Karel can react to whatever it actually finds.
02

A More Useful Example

Combine an if statement with a for loop: check for a ball on every corner along a path, and pick it up if one's there.

function main() { for (var i = 0; i < 5; i++) { if (ballPresent()) { takeBall(); } move(); } }

Karel walks 5 squares. On each one, it checks for a ball first — if there's one, it picks it up — then moves to the next square either way.

03

Common Mistakes

Mistake 1

Forgetting the condition needs parentheses

if frontIsClear() { // missing ( )

The condition always goes inside its own set of parentheses: if (frontIsClear()).

Mistake 2

Using the wrong condition

frontIsClear() and frontIsBlocked() are opposites. Mixing them up flips your logic backward — Karel does the opposite of what you meant.

Mistake 3

Expecting the if to run every time

An if statement is conditional by definition — if the condition is false, that code is skipped, not delayed. It just doesn't run at all that time.

A condition is a yes/no question. An if statement runs code only when the answer is true.

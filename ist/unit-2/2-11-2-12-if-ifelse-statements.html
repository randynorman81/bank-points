2.11 — If Statements and Conditionals

🔔 Bell Ringer — Think About It
  1. An if statement lets Karel react differently depending on what it actually finds in the world, instead of blindly doing the same thing every time. Why would a program that can only ever do the exact same steps in the exact same order eventually break the first time something unexpected happens?
  2. "Opposite Day" has Karel do the reverse of what it would normally do. If flipping just one condition in an if/else statement can flip an entire program's behavior, how careful do you think a programmer needs to be when writing that one line?
  3. An if statement with no else just skips doing anything when the condition is false. An if/else always does something, no matter what. Can you think of a real situation where "do nothing" is actually the smarter choice, versus one where you'd always want a backup plan?
  4. If "Right Side Up" and "Right vs Left Square" both depend on Karel correctly checking its surroundings before acting, what do you think happens to the rest of the program if that very first check is wrong?
